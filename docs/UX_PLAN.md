## 0. 문서 목적과 결정 범위

이 문서는 확정된 제품 요구사항을 사용자가 이해하고 사용할 수 있는 화면 구조와 흐름으로 번역한다. 새로운 제품 기능을 추가하거나 권한·AI 행동·세션 규칙을 변경하지 않는다.

- 제품 행동은 `PRODUCT_SPEC.md`를 우선한다.
- 이 문서의 navigation, 화면 hierarchy, disclosure 방식은 UX 구현 기준이다.
- 참가자에게 보이는 상태는 서버가 확정한 상태를 표현하며 client가 추측해 만들지 않는다.
- `AI_PRIVATE`, Discussion Metrics, Living Wiki와 내부 평가 정보는 허용된 participant-facing projection 외에는 노출하지 않는다.
- 운영자용 Book Context Builder는 참가자용 서비스와 별도 UX track으로 다룬다.

## 1. UX North Star

### 1.1 핵심 경험

> 참가자가 AI를 사용하는 느낌보다, 한 권의 책을 가운데 두고 서로의 생각이 깊어지는 경험을 만든다.

### 1.2 핵심 사용자 과업

참가자의 핵심 과업은 기능을 탐색하는 것이 아니라 다음 흐름을 막힘없이 완주하는 것이다.

1. 나에게 맞는 토론을 찾는다.
2. 대화에 들어가기 전 필요한 맥락을 이해한다.
3. 선택적으로 생각을 준비한다.
4. 현재 의제를 놓치지 않고 다른 사람의 생각을 읽고 응답한다.
5. 토론의 전환과 마무리를 이해한다.
6. 토론 후 남은 생각을 공동 기록에서 다시 확인한다.

방장의 핵심 과업은 토론을 직접 진행하는 것이 아니라 세션 운영이 끊기지 않게 하는 것이다.

### 1.3 UX 원칙

1. **대화 우선**  
   참가자 메시지가 가장 높은 정보 우선순위를 가진다. AI·책 정보·운영 control은 대화를 보조한다.

2. **현재 맥락의 지속성**  
   책, 현재 의제, 세션 단계와 남은 시간을 사용자가 필요할 때 즉시 확인할 수 있게 한다.

3. **AI의 절제된 존재감**  
   좋은 흐름에서 AI가 보이지 않는 상태를 정상으로 설계한다. AI 발언은 assistant bubble이 아니라 대화 사이의 편집적 표식처럼 표현한다.

4. **선택적 준비**  
   사전 입력을 숙제나 참가 조건처럼 보이게 하지 않는다. 비어 있어도 자연스럽게 대기하고 참여할 수 있어야 한다.

5. **권한의 맥락화**  
   방장 control은 필요한 단계와 위치에만 제공한다. 일반 참가자 화면에 사용할 수 없는 운영 control의 자리를 남기지 않는다.

6. **상태 신뢰성**  
   참가 완료, 메시지 전송, 시작, 연장, 종료는 서버 성공 확인 이후에만 확정 상태로 표현한다.

7. **회복 가능한 실시간 경험**  
   재연결, 실패와 지연이 발생해도 읽던 대화와 작성 중인 문장을 잃지 않고 현재 서버 상태로 안전하게 복귀한다.

8. **조용한 접근성**  
   중요한 변화는 문구·아이콘·색을 함께 사용하되 실시간 메시지와 매초 타이머로 인지 부담을 만들지 않는다.

## 2. 사용자 역할과 화면 관점

| 역할 | 주된 목표 | 항상 알아야 하는 것 | 필요할 때만 보는 것 |
| --- | --- | --- | --- |
| 참가자 | 생각을 나누고 다른 관점을 만남 | 현재 의제, 단계, 남은 시간, 내 메시지 상태 | 참가자 목록, 방·책 상세, 나가기 |
| 방장 | 참가자와 동일하게 토론하면서 세션 운영 | 시작 가능 여부, 연장 결정 필요 여부 | 방 설정, 참가자 관리, AI 도움 요청, 토론 종료 |
| 운영자 | 안전한 Book Context Pack 준비 | Pack 상태, Coverage, blocker | 출처 비교, diff, version history |

방장 여부는 별도 mode 전환으로 표현하지 않는다. 동일한 토론 화면 위에 해당 단계에서 필요한 방장 control만 추가한다.

## 3. 기본 사용자 시나리오

### 3.1 Happy Path

```text
방 생성
→ 참가자가 방 검색
→ 참가 패스워드 입력
→ 대기실 입장
→ 선택적 사전 입력
→ 방장이 토론 시작
→ AI Opening
→ Core Discussion
→ 연장 또는 마무리 결정
→ Synthesis
→ Closing 마지막 한 줄
→ 공식 종료
→ 오늘의 토론 기록
```

### 3.2 핵심 분기

- 세션 시작 후 참가: 현재 단계·의제·남은 시간을 확인한 뒤 `토론에 참여하기`
- 재접속: 누락 메시지·단계·남은 시간·권한 동기화 후 composer 활성화
- 정원 마감: 참가 입력 비활성화, 대기자 명단 없음
- AI 지연 또는 실패: 인간 대화는 계속하고 단계별 fallback만 표시
- 방장 미응답: 연장 결정 제한 시각이 지나면 자동으로 Synthesis 전환
- 방장 강제 종료: Synthesis와 Closing을 건너뛰고 읽기 전용 종료 화면으로 이동
- 기록 생성 지연: 전체 대화는 즉시 열람하고 기록 영역만 생성 상태 표시

## 4. 정보구조

### 4.1 App navigation

인증 이후의 기본 global header는 이동 navigation과 생성 action을 분리한다.

1. **내 토론** — 진행 중, 예정, 종료로 이동하는 기본 destination
2. **토론 찾기** — 방 제목·책 제목·저자 검색 destination
3. **토론 만들기** — navigation tab이 아니라 모든 로그인 회원에게 제공하는 독립된 primary action

Desktop에서는 service identity를 왼쪽, `내 토론 / 토론 찾기` text navigation을 가운데, icon-only `토론 만들기`와 profile avatar를 오른쪽에 둔다. 현재 destination은 얇은 underline 하나로만 표시하고 tab을 pill이나 filled button으로 만들지 않는다. `토론 만들기`에는 accessible name과 tooltip을 제공한다.

Mobile 일반 화면은 hamburger, 가운데 service identity, icon-only 만들기와 profile avatar를 한 줄에 둔다. hamburger menu가 `내 토론 / 토론 찾기 / 토론 만들기`를 text row로 펼치며 별도 하단 navigation은 사용하지 않는다. 실시간 토론에서는 전역 header를 감추고 `뒤로 / 책·방 / 시간 / 참가자 / 더보기`만 있는 토론 context header로 바꾼다.

account menu는 별도 신원 card나 이메일을 반복하지 않고 현재 이름, `프로필 설정`, `로그아웃`만 제공한다. `ADMIN` 계정에만 `운영` 구획 아래 `Book Context 관리`를 추가해 일반 토론 navigation과 시각적으로 분리한다.

`토론 찾기` 첫 화면은 넓은 editorial heading과 가장 중요한 단일 search를 먼저 보여준 뒤, `곧 시작해요 / 지금 참여 가능`처럼 product state에서 파생되는 browse section을 충분한 여백으로 이어간다. 장르·추천·인기 같은 MVP 밖 filter와 ranking은 추가하지 않는다. room image를 새로 요구하지 않고 책 표지를 dominant visual로 사용한다.

2026-09-02 Fable Club 화면에서 참고한 범위는 `가운데 정렬된 단순 navigation / 넓은 search hero / 여백이 큰 section browsing / mobile hamburger` 패턴이다. 공개 club follower 수, 장르 chip, 인물 사진, 추천 ranking과 app 설치 유도는 책은양념 MVP 요구가 아니므로 가져오지 않는다.

### 4.2 Object hierarchy

```text
책
└── 토론방
    ├── 참가 membership
    ├── 대기실과 사전 입력
    ├── 실시간 세션
    │   ├── 현재 의제
    │   ├── 대화와 AI Host 발언
    │   ├── 연장·Synthesis·Closing
    │   └── 참가자 상태
    └── 종료 결과
        ├── 오늘의 토론 기록
        ├── 전체 대화
        ├── PUBLIC 사전 입력
        └── 마지막 한 줄
```

사용자에게는 `토론방`과 `세션`을 별개의 관리 개념으로 학습시키지 않는다. 화면 제목과 navigation에서는 일관되게 `토론`을 사용하고, 상태 변화로 대기실·토론 중·마무리·종료를 표현한다.

### 4.3 Route-level 화면 구조

| 화면 | 1차 목적 | Primary action | Secondary action |
| --- | --- | --- | --- |
| 로그인·가입 | 계정 접근 | 로그인 / 가입 | 비밀번호 재설정 |
| 내 토론 | 돌아가야 할 토론 찾기 | 진행 중 토론 입장 | 예정·종료 토론 확인 |
| 토론 찾기 | 참여할 토론 발견 | 방 상세 보기 | 검색어 수정 |
| 방 상세·참가 | 참가 전 조건 확인 | 패스워드로 참여 | 돌아가기 |
| 토론 만들기 | 책과 운영 조건 설정 | 토론방 만들기 | 취소 |
| 대기실 | 시작 전 맥락·참가자·생각 준비 | 사전 입력 저장 / 토론 시작(방장) | 참가 취소·방 설정 |
| 시작 후 진입 안내 | 늦은 참가자가 현재 상황 이해 | 토론에 참여하기 | 돌아가기 |
| 실시간 토론 | 사람들의 대화 | 메시지 보내기 | 답장·참가자 확인 |
| 연장 결정 | 종료 임박 상태 이해 | 15분 연장 / 마무리(방장) | 없음 |
| Synthesis | 관점 구조 확인과 reflection | reflection 메시지 | 없음 |
| Closing | 마지막 한 줄 남기기 | 제출 | 수정·삭제·건너뛰기 |
| 종료된 토론 | 공동 사고 기록 재방문 | 기록 읽기 | 전체 대화·사전 입력 확인 |
| 프로필 | 이름·계정 관리 | 이름 저장 | 비밀번호·탈퇴 흐름 |

## 5. 참가자 Journey Map

| 단계 | 참가자 질문 | 핵심 행동 | UX 응답 | 실패·불안 완화 |
| --- | --- | --- | --- | --- |
| 발견 | 어떤 토론에 들어갈까? | 방·책·저자 검색 | 책 표지, 방 제목, 방장, 시각, 상태, 인원 표시 | `토론 중`과 `참여 가능`을 별도 표기 |
| 참가 | 내가 들어갈 수 있나? | 방 상세 확인, 패스워드 입력 | 참가 조건과 현재 상태를 먼저 보여주고 password는 action 시 요청 | 오류 시 입력을 비우고 정확한 안내, 정원 경합 별도 안내 |
| 대기 | 지금 무엇을 하면 되지? | 참가자 확인, 선택적 사전 입력 | 시작 예정 시각, 접속/최소 인원, `선택사항` 문구를 상단에 명시 | 준비 완료처럼 평가받는 느낌 제거 |
| 준비 | 어디까지 공개되지? | 항목 작성, 공개 범위 지정 | 각 항목 안에서 `모두에게 공개 / AI에게만 공개`를 선택하고 설명 | 저장 결과, 시작 후 잠금 시점을 명확히 표시 |
| 시작 | 언제 시작하지? | 방장의 시작을 기다림 | 시작 조건과 대기 상태를 참가자용 문구로 표현 | 시작 버튼 자리나 비활성 control은 참가자에게 노출하지 않음 |
| 토론 | 지금 무엇을 이야기하지? | 읽기, 쓰기, inline reply | 현재 의제를 sticky하게 유지하고 대화를 가장 넓게 배치 | 과거 읽는 중 자동 scroll 금지, 새 메시지 개수 제공 |
| 전환 | 왜 흐름이 바뀌었지? | AI 개입·의제 전환 확인 | AI 발언과 system 상태를 참가자 메시지와 분리 | 내부 평가나 AI thinking state는 노출하지 않음 |
| 종료 임박 | 계속하나, 끝나나? | 방장 결정을 기다림 | AI 의견과 방장 결정권을 분리해 표시 | 7분·5분 경계를 숫자와 문구로 안내 |
| Synthesis | 오늘 무엇이 갈렸나? | 정리 읽기, 짧은 reflection | 관점 차이를 병렬로 보존하고 새 주제를 열지 않음 | AI 실패 시 Closing으로 넘어간다는 상태 안내 |
| Closing | 꼭 써야 하나? | 마지막 한 줄 제출 또는 건너뛰기 | 선택사항, 남은 시간, 다른 사람에게 아직 안 보임을 명시 | 제출 상태와 수정 가능 시점을 표시 |
| 결과 | 무엇이 남았나? | 기록·대화 재열람 | `오늘의 토론 기록`을 첫 화면으로, 원본 대화는 보조 navigation | 생성 중이어도 대화는 즉시 열람 가능 |

## 7. 핵심 화면별 UX 구조

### 7.1 내 토론

정보 우선순위:

1. 현재 참여 가능한 `진행 중` 토론
2. 시작 시각이 가까운 `예정` 토론
3. 최근 종료된 토론

상단은 `진행 중 / 예정 / 종료` 세 분류만 사용한다. 별도의 통계, 추천, 활동 요약은 추가하지 않는다.

각 항목은 방 제목, 책, 역할, 상태, 시작 예정 시각, 현재/최대 인원만 표시한다. 항목 전체를 진입 control로 사용하고 별도의 `입장하기 / 보기` 버튼을 반복하지 않는다. 취소된 토론은 `종료`에 남기되 열 수 없는 상태 row로 표시한다.

빈 상태에서는 토론 찾기와 토론 만들기 두 행동을 제공하되 하나를 과장된 dashboard card로 만들지 않는다. 세 분류 중 한 곳만 비어 있으면 현재 분류와 직접 관련된 action 하나만 보여준다.

### 7.2 토론 찾기와 참가

- 검색창 하나로 방 제목·책 제목·저자를 검색한다.
- 결과 item에서 진행 상태와 참가 가능 여부를 서로 다른 label로 표시한다.
- password는 검색 결과 card에 직접 노출하지 않고 방 상세에서 참여 action을 실행할 때 요청한다.
- 이미 등록한 사용자는 password 대신 `대기실로 돌아가기` 또는 `토론으로 돌아가기`를 본다.

### 7.3 토론 만들기

권장 순서는 다음과 같다.

1. **책 선택** — 검색·정렬·판본 구분, 선택 후 짧은 소개 확인
2. **토론 정보** — 방 제목, 시작 예정 시각, 참가 password, 최소·최대 인원
3. **최종 확인** — 생성될 방과 필수 조건 확인 후 생성

단계가 바뀌어도 선택한 책과 작성값을 유지한다. password의 외부 전달은 서비스 밖에서 이루어진다는 안내를 생성 완료 화면에 짧게 제공한다.

### 7.4 대기실

Desktop과 Mobile 공통 hierarchy:

1. 책·방 identity와 시작 예정 시각
2. 시작 상태 — 등록 인원과 현재 접속 인원을 분리
3. 참가자 목록
4. 내 사전 입력
5. 다른 참가자의 PUBLIC 사전 입력

대기실의 참가자 목록과 사전 입력은 desktop에서도 한 줄에 병치하지 않는다. `시작 상태 → 참가자 목록 → 내 사전 입력 → PUBLIC 입력` 순서의 단일 reading flow를 유지한다. 방장 start panel은 시작 가능 여부가 변해도 안정된 위치에 두고, 일반 참가자에게는 같은 자리에 빈 영역을 남기지 않는다.

사전 입력 card에는 `선택사항`과 `토론 시작 전까지 수정할 수 있어요`를 함께 표시한다. 공개 범위는 전체 form 공통 설정이 아니라 각 항목 바로 아래에서 선택한다.

### 7.5 실시간 토론방

고정 정보 hierarchy:

1. compact book context: 표지, 제목
2. phase, 남은 시간, 현재 접속 인원
3. current topic
4. message timeline
5. composer

Desktop에서도 persistent 3-column dashboard를 사용하지 않는다. conversation column을 중심에 두고 참가자 목록과 방장 control은 disclosure로 연다.

AI Host 발언은 `책은양념 · AI Host` label, 차분한 surface와 divider로 구분한다. participant avatar, 강한 accent, mascot, typing animation을 사용하지 않는다.

### 7.6 연장 결정

토론방을 덮는 blocking modal보다 current topic 아래의 session state region을 우선한다. 참가자는 대화를 계속 읽고 쓸 수 있어야 한다.

- 모든 참가자: 종료 임박, AI 의견, 방장 결정 대기 상태
- 방장: `15분 연장`, `마무리하기`
- 결정 후: 변경된 상태와 종료 시각을 한 번 명확히 알리고 대화 surface로 복귀

### 7.7 Synthesis와 Closing

Synthesis에서는 일반 채팅을 유지하되 AI의 정리와 reflection 요청이 현재 의제보다 높은 위치를 갖는다. Closing이 시작되면 일반 composer를 제거하고 마지막 한 줄 전용 input으로 교체한다.

Closing 화면에는 다음 세 정보만 강조한다.

1. 마지막 한 줄은 선택사항
2. 다른 참가자의 답은 종료 전 보이지 않음
3. 남은 시간과 제출·건너뛰기 상태

### 7.8 종료된 토론

첫 진입은 결과 중심으로 구성한다.

1. 책·방·참여자·종료 시각
2. 오늘의 토론 기록
3. 참가자가 직접 남긴 마지막 한 줄
4. 전체 대화
5. PUBLIC 사전 입력

핵심 쟁점·관점·변화·남은 질문은 이름 없이 보여주고 마지막 한 줄에만 제출 당시 이름을 붙인다. 결과 생성 중에는 동일 위치에 안정된 skeleton과 상태를 보여주며 전체 대화 navigation은 즉시 사용할 수 있게 한다.

기록 생성 실패·대화 부족·읽기 전용 원본과 privacy projection의 상세 기준은 `docs/DISCUSSION_RESULTS_UX.md`를 따른다.

### 7.9 방 설정

방장만 접근하며 한 화면에서 현재 단계에 맞는 변경 가능 항목만 편집한다.

- 시작 전에는 방 제목, 시작 예정 시각, 참가 패스워드, 최소·최대 참가 인원을 편집한다.
- 책은 방장 외 등록 참가자가 없을 때만 변경 control을 제공한다. 변경할 수 없으면 disabled select를 남기지 않고 현재 책과 잠금 이유를 짧게 표시한다.
- 시작 후에는 참가 패스워드와 최대 참가 인원만 편집한다. 제목·책·예정 시각·최소 인원은 form field가 아니라 읽기 전용 요약으로 보인다.
- 패스워드 변경은 기존 참가자에게 영향을 주지 않고 이후 새 참가자에게만 적용된다는 내용을 저장 시점에 한 번 확인한다.
- 최대 인원은 현재 등록 인원보다 작게 줄일 수 없고 15명을 넘길 수 없다. 불가능한 증감 control은 비활성화한다.
- 시작 전 `토론 취소`, 시작 후 `토론 종료`는 일반 저장 action과 분리한 마지막 영역에 둔다. 둘 다 대상과 되돌릴 수 없는 영향을 보여주는 확인 dialog를 거친다.
- 설정 저장과 위험 action은 server 성공 이후에만 화면 상태를 변경한다.

### 7.10 로그인·회원가입·비밀번호 재설정

인증 전 화면에는 서비스 navigation을 노출하지 않고 `책은양념` identity와 현재 form만 중앙에 둔다. 화면 폭은 desktop에서도 한 열로 제한한다.

- 로그인: 이메일, 비밀번호, `로그인`, `비밀번호 재설정`, `회원가입`만 제공한다.
- 로그인 실패는 계정 존재 여부를 구분하지 않고 `이메일 또는 비밀번호를 확인해주세요`를 form 상단이 아니라 입력과 action 사이에 표시한다.
- 회원가입: 프로필 이름, 이메일, 비밀번호를 한 번에 입력한다. 프로필 이름이 토론에서 보이는 이름임을 field label 안에서 이해할 수 있게 한다.
- 이메일 중복은 `이미 사용 중인 이메일입니다`를 이메일 field에 연결한다. 이메일 확인 대기 화면은 만들지 않고 가입 성공 후 바로 로그인 상태로 전환한다.
- 비밀번호 재설정 요청은 이메일 하나만 받는다. 제출 후 이메일 존재 여부와 무관하게 동일한 메일 안내 화면을 보여준다.
- 재설정 link callback은 새 비밀번호와 확인값만 받는다. 완료 후 `로그인`으로 돌아간다.
- 만료·사용 완료 link는 기술 오류 대신 `재설정 링크가 만료되었어요`와 `재설정 메일 다시 받기`를 제공한다.
- 회원가입과 재설정의 Turnstile managed challenge는 필요할 때만 form 안에 나타나며 기본 화면에 보안 설명 panel을 상시 노출하지 않는다.
- provider 원문 오류, 계정 존재 여부, token과 내부 인증 상태를 사용자에게 노출하지 않는다.

### 7.11 운영자 Book Context Builder

Builder는 일반 토론 navigation과 분리된 ADMIN 전용 작업 공간이다. 일반 회원 화면에 운영자 상태를 표시하지 않으며 참가하지 않은 토론 데이터로 이동하는 진입점을 제공하지 않는다.

- 첫 화면은 Pack 목록과 `새 Pack` action만 제공하고 통계 dashboard를 만들지 않는다.
- 새 Pack은 책 제목과 저자로 시작하며 조사 stage와 실패·재시도 상태를 작업 단위로 보여준다.
- Draft 편집은 7개 section coverage, 항목 유형, evidence state와 source 관계를 같은 hierarchy에서 검수할 수 있게 한다.
- `정보 부족 / 출처 충돌 / 복수 해석`을 빈칸이나 오류처럼 숨기지 않는다.
- 항목 재생성은 운영자 수정본을 덮어쓰기 전에 현재본과 생성본 diff를 확인한다.
- Review에서는 hard blocker와 운영자가 확인할 warning을 분리하고 모든 section을 억지로 `READY`로 만들도록 유도하지 않는다.
- Publish는 신규 방에 미치는 영향과 기존 활성 version의 Retire를 확인한 뒤 실행한다.
- Published는 직접 수정하지 않고 새 Draft version을 만든다. Publish 취소는 Retired 전환이며 사유를 필수로 받는다.
- 저장, 재생성 반영, 상태 전이와 Publish는 server 성공 이후에만 확정 상태로 표시한다.

상세 화면·상태 기준은 `docs/BOOK_CONTEXT_BUILDER_UX.md`를 따른다.

### 7.12 프로필·계정 설정

프로필 설정은 최대 540px 한 열에서 이름, 계정, 탈퇴 순서로 구성한다. 본문 신원 요약과 중복 section heading을 두지 않고 이름과 이메일을 각각 한 번만 표시한다. 이름 변경은 저장 성공 이후 새 메시지와 새 토론에만 적용하고 과거 메시지와 마지막 한 줄의 당시 이름은 유지한다.

- 첫 화면은 이름 input과 저장 action, `이메일 / 비밀번호 재설정 / 로그아웃` 세 행, `계정 탈퇴 알아보기`로 축약한다.
- 이메일은 읽기 전용으로 표시하고 MVP에 이메일 변경·프로필 이미지 업로드를 추가하지 않는다.
- 비밀번호 재설정과 로그아웃은 계정 action으로 분리한다.
- 첫 화면에는 `계정 탈퇴 알아보기`만 두고 삭제 영향과 blocker를 확인한 뒤에만 현재 비밀번호를 받는다.
- 진행 중 실제 참여, 예정 방장과 ADMIN 역할은 각각 종료·권한 이전 또는 취소·역할 해제 후 탈퇴할 수 있다.
- 탈퇴 시 식별정보와 `AI_PRIVATE`는 삭제하고 공동 기여는 `탈퇴한 사용자`로 익명화해 유지한다.
- 같은 이메일로 다시 가입할 수 있지만 이전 계정은 복구되지 않는다.
- 최종 탈퇴와 완료 상태는 server 성공 이후에만 반영한다.

상세 흐름은 `docs/PROFILE_ACCOUNT_UX.md`를 따른다.

## 9. 오류·예외 상태 UX

| 상황 | 사용자-facing 처리 |
| --- | --- |
| password 오류 | 입력값을 비우고 `패스워드가 올바르지 않습니다` |
| 반복 오입력 제한 | `잠시 후 다시 시도해주세요`, 입력 비활성 |
| 참가 직전 정원 마감 | `방금 정원이 마감되었습니다`, membership 미생성 |
| 시작 조건 미충족 | 방장 start panel에 부족한 접속 인원 또는 예정 시각 표시 |
| 메시지 전송 중 | 확정 메시지와 구분되는 pending 상태 |
| 메시지 실패 | 내용 유지, `다시 보내기` 제공 |
| 과거 대화 읽는 중 새 메시지 | 자동 scroll 대신 `새 메시지 N개` |
| 연결 끊김 | 기존 대화는 유지하고 composer·운영 control 잠금 |
| 재연결 | `대화를 다시 맞추고 있어요` 후 snapshot 동기화 완료 시 입력 복구 |
| AI 자동 개입 실패 | 별도 기술 오류를 알리지 않고 인간 대화 지속 |
| Opening 지연 | `AI 응답 준비 중`, 채팅 허용 |
| Synthesis 실패 | 짧은 안내 후 Closing 전환 |
| 기록 생성 중 | 기록 영역 상태 표시, 전체 대화는 즉시 열람 |
| 강제 종료 | `방장이 토론을 종료했습니다`, 읽기 전용 이동 |

내부 error message, model 이름, stack trace, Discussion Metrics는 어떤 오류 상태에서도 노출하지 않는다.

## 10. 반응형 원칙

### Mobile 360px+

- compact header, current topic과 composer를 안정적으로 유지한다.
- 가상 keyboard가 열려도 작성 중 문장과 보내기 action을 가리지 않는다.
- 참가자 목록, 책 상세, 방장 control은 bottom sheet 또는 dialog로 연다.
- current topic은 sticky 상태에서 최대 두 줄, 사용자가 펼쳐 전체를 읽을 수 있게 한다.
- message text는 16px을 유지하고 bubble 없는 문서형 흐름을 보존한다.
- Closing input과 countdown이 composer 영역을 완전히 대체해 두 입력이 동시에 보이지 않게 한다.

### Tablet/Desktop

- 전체 shell 최대 1040px, conversation column 최대 720px을 기준으로 한다.
- 실제로 동시에 비교해야 하는 form이나 운영 화면에서만 제한적인 2-column을 사용할 수 있다.
- 실시간 토론은 conversation 중심 1-column을 유지한다.
- hover에서 나타나는 reply action은 focus와 touch에서도 동일하게 접근 가능해야 한다.

## 11. Content design 원칙

- 내부 용어보다 사용자가 다음 행동을 이해하는 문장을 쓴다.
- 일반적인 행동은 icon-only control과 accessible label로 간결하게 표현하고, 텍스트는 판단이나 확인이 필요한 순간에 집중한다.
- 정상 상태를 문장으로 계속 설명하지 않는다. 오류·변경·행동 필요 상태만 짧은 icon + label로 노출한다.
- 되돌릴 수 없거나 권한이 바뀌는 행동은 아이콘으로 축약하지 않고 대상·영향·실행 동사를 명시한다.
- `사전 입력`에는 항상 `선택사항`을 함께 보여준다.
- `AI_PRIVATE`의 사용자용 label은 `AI에게만 공개`로 하고 “원문과 작성자는 다른 참가자에게 보이지 않아요”를 인접해 설명한다.
- `세션`, `membership`, `Synthesis`, `projection` 같은 내부 용어를 일반 UI에 그대로 사용하지 않는다.
- 사용자-facing 단계는 `토론 중 / 연장 중 / 마무리 중 / 종료`를 사용한다.
- 되돌릴 수 없는 행동은 결과를 먼저 설명하고 동사 label을 구체적으로 쓴다.
- AI 의견과 확정 사실을 같은 어조로 표현하지 않는다.

### 핵심 문구 기준

| 상황 | 권장 문구 |
| --- | --- |
| 사전 입력 제목 | 토론 전에 생각을 남겨보세요 · 선택사항 |
| AI 공개 범위 | AI에게만 공개 · 원문과 작성자는 다른 참가자에게 보이지 않아요 |
| 참가자 시작 대기 | 방장이 곧 토론을 시작할 예정이에요 |
| 접속 인원 부족 | 현재 접속 2명 · 시작하려면 1명이 더 필요해요 |
| 늦은 참가 | 토론이 이미 진행 중이에요. 지금 나누는 질문과 남은 시간을 확인하고 참여해주세요 |
| 재연결 | 대화를 다시 맞추고 있어요. 잠시 후 메시지를 보낼 수 있습니다 |
| Closing | 오늘 대화 후 가장 남는 생각을 한 문장으로 남겨주세요 · 선택사항 |
| 기록 생성 | 오늘의 토론 기록을 정리하고 있어요. 전체 대화는 지금 볼 수 있습니다 |

## 12. 접근성 검증 기준

- 방 검색, password 참가, 사전 입력, 메시지 작성, Closing 제출을 keyboard만으로 완료할 수 있다.
- dialog와 menu가 열리고 닫힐 때 초점이 올바르게 이동·복귀한다.
- phase, 종료 임박, 연결·전송 실패를 색만으로 전달하지 않는다.
- timer는 7분·5분·1분, Closing 시작·종료 같은 핵심 경계만 screen reader에 알린다.
- 새 메시지는 사용자가 최신 위치를 보고 있을 때만 polite announcement한다.
- 참가자·AI·system 메시지와 inline reply 관계를 semantic text로 구분한다.
- 200% zoom과 360px에서 horizontal page scroll 없이 핵심 flow가 작동한다.

## 13. 사용성 검증 시나리오

프로토타입에서 다음 과업을 순서대로 검증한다.

1. 사용자가 원하는 책의 토론을 찾고 password로 참가할 수 있는가?
2. 사전 입력이 선택사항임을 이해하고 각 항목의 공개 범위를 설명할 수 있는가?
3. 방장이 왜 아직 시작할 수 없는지, 언제 시작할 수 있는지 이해하는가?
4. 참가자가 현재 의제와 남은 시간을 놓치지 않고 특정 메시지에 답할 수 있는가?
5. 종료 7분 전 AI 의견과 방장 결정권의 차이를 이해하는가?
6. Closing에서 제출하지 않아도 된다는 점과 다른 사람의 입력이 아직 보이지 않는다는 점을 이해하는가?
7. 종료 후 공동 기록과 전체 대화의 차이를 이해하고 원하는 내용을 다시 찾을 수 있는가?
8. 연결 끊김과 메시지 실패에서 데이터가 사라졌다고 오해하지 않고 복구할 수 있는가?

인앱 설문은 만들지 않는다. 파일럿 인터뷰와 관찰에서 막힌 지점, 잘못 이해한 상태, 불필요한 AI 주목도를 기록한다.

## 14. 와이어프레임 제작 순서

화면 수가 아니라 제품 가설을 가장 빠르게 검증하는 순서로 제작한다.

1. 실시간 토론방 — 일반 흐름, AI 없음, AI 개입, reply, message 실패
2. 대기실 — 참가자/방장, 선택적 사전 입력과 시작 조건
3. 연장 결정 → Synthesis → Closing
4. 오늘의 토론 기록과 전체 대화
5. 토론 찾기 → password 참가 → 시작 후 늦은 참가
6. 토론 만들기와 책 선택
7. 내 토론·로그인·프로필
8. reconnect와 주요 destructive confirmation

운영자 Builder는 위 참가자 MVP flow의 wireframe이 안정된 뒤 별도 IA와 작업 흐름으로 설계한다.
