> Status: Proposed UX baseline

> Related decisions: `docs/DECISIONS.md` PRODUCT-009, PRODUCT-023, PRODUCT-024

## 0. 목적과 범위

종료된 토론은 회의록 보관함이 아니라 참가자가 함께 만든 사고의 구조를 다시 읽는 공간이다. 첫 진입에서는 익명화된 공식 기록을 우선하고, 원본 대화와 사전 입력은 근거를 다시 확인하는 보조 경로로 둔다.

MVP 범위:

- 실제 참여자와 방장의 읽기 전용 재열람
- 「오늘의 토론 기록」, 전체 대화, PUBLIC 사전 입력, 제출된 마지막 한 줄
- 작성자 본인에게만 자신의 `AI_PRIVATE` 사전 입력 재노출
- 기록 생성 중·재시도 중·실패·대화 부족 상태
- 방장에게만 최초 공식 기록 실패 후 재시도

MVP에서 제외:

- 공개 링크, 비회원 공개, SNS 공유
- 파일 다운로드·내보내기
- 성공한 공식 기록의 수정·삭제·재생성
- 종료 후 메시지·사전 입력·마지막 한 줄 추가 또는 변경
- 참가자별 AI 분석 리포트

## 1. 진입과 접근

- `내 토론 > 종료`의 row 전체로 진입한다.
- 방장과 실제 참여자만 접근할 수 있다.
- 참가 등록만 한 no-show와 방장이 내보낸 사용자는 접근할 수 없다.
- 권한 확인 전 종료된 방 내용을 잠깐 렌더링하지 않는다.
- 종료된 방은 검색 결과에 노출하지 않는다.

## 2. 공통 화면 구조

정보 순서:

1. 내 토론으로 돌아가는 icon-only back
2. 책 표지, 방 제목, 책 제목·저자, 종료 시각과 상태
3. 실제 참여자 수와 명단을 여는 icon-only control
4. local navigation: `오늘의 토론 기록 / 전체 대화 / 사전 입력`
5. 선택한 읽기 전용 내용

공개·다운로드·편집 action을 상단에 만들지 않는다. 참가자 명단은 주 콘텐츠와 경쟁하지 않도록 dialog 또는 sheet로 연다.

## 3. 오늘의 토론 기록

공식 기록은 다음 순서를 유지한다.

1. 오늘의 핵심 쟁점 2~4개
2. 쟁점별 관점 지도
3. 오늘 생긴 변화와 확장
4. 남은 질문
5. 참가자가 직접 남긴 마지막 한 줄

### 3.1 표현 원칙

- 핵심 쟁점·관점·변화·질문에는 참가자 이름을 붙이지 않는다.
- 관점은 합의된 결론처럼 합치지 않고 병렬로 보여준다.
- `누군가 생각을 바꿨다`고 단정하지 않고 공개 대화에서 확인 가능한 변화만 기술한다.
- 책 밖으로 확장된 논의를 잘못된 이탈처럼 표시하지 않는다.
- 내부 Discussion Metrics, Final Wiki, evidence reference, 모델·생성 정보를 노출하지 않는다.
- 성공한 공식 기록에는 편집·삭제·다시 생성 action을 제공하지 않는다.

### 3.2 마지막 한 줄

- 마지막 한 줄은 기록 본문과 시각적으로 분리한다.
- 제출 당시 프로필 이름과 함께 표시한다.
- 미제출 참가자를 빈칸이나 미완료 상태로 표시하지 않는다.
- 이후 프로필 이름 변경을 소급 적용하지 않는다.

## 4. 전체 대화

- 작성 당시 이름, 시각, AI Host 구분과 inline reply 관계를 보존한다.
- composer, reply, reaction, AI 도움과 운영 menu를 제거한다.
- 종료 전에 확정된 message만 표시하고 pending message를 복원하지 않는다.
- 대화 시작과 종료 경계를 짧은 system row로 표시한다.
- MVP에 정의되지 않은 대화 검색·필터·다운로드를 추가하지 않는다.

## 5. 사전 입력

- `PUBLIC` 항목은 작성자 이름과 함께 모든 실제 참여자에게 표시한다.
- 현재 사용자의 `AI_PRIVATE` 항목만 별도 `내 준비` 영역에 표시한다.
- 사용자 label은 `AI에게만 공개`를 유지하고 다른 참가자의 private 항목 수나 존재 여부도 표시하지 않는다.
- 모든 항목은 읽기 전용이며 공개 범위도 바꿀 수 없다.

## 6. 기록 생성 상태

### 6.1 생성 중

- 기록 영역의 hierarchy와 높이를 유지하는 안정된 skeleton을 사용한다.
- `오늘의 토론 기록을 정리하고 있어요`와 compact progress만 표시한다.
- `전체 대화`와 `사전 입력`은 즉시 이동할 수 있다.
- 생성 상태를 page 전체 loading이나 modal로 막지 않는다.

### 6.2 재시도 중

- 생성 중과 같은 자리에서 `다시 정리하고 있어요`를 표시한다.
- 중복 action을 막고 종료 상태나 원본 대화를 변경하지 않는다.

### 6.3 자동 재시도 실패

- 일반 참가자에게는 실패 사실과 전체 대화가 유지된다는 점만 표시한다.
- 방장에게만 `다시 생성하기` text action을 제공한다.
- 실행 후 server가 job을 수락하기 전에는 `재시도 중`으로 바꾸지 않는다.
- 성공한 공식 기록에는 재시도 action을 다시 만들지 않는다.

### 6.4 충분한 대화가 없음

- 내용을 꾸며내거나 빈 section을 만들지 않는다.
- `기록을 만들기에 충분한 대화가 없습니다`를 공식 결과 상태로 표시한다.
- 원본 대화와 사전 입력은 계속 읽을 수 있다.
- 실패로 표현하거나 재생성을 권하지 않는다.

## 7. 참여자 명단

- 실제 참여자만 표시하고 방장은 `방장`을 함께 표시한다.
- 접속 상태, 발언량, 침묵, 활동 점수와 참여 시간은 표시하지 않는다.
- 명단 dialog가 열리면 내부 첫 control로 focus를 이동하고 닫힌 뒤 실행 control로 복귀한다.

## 8. 반응형과 접근성

- desktop에서는 기록 본문을 최대 720px 중심 열로 제한하고 관점만 필요한 범위에서 2-column으로 배치한다.
- 736px 이하에서는 metadata와 local navigation을 자연스럽게 줄바꿈한다.
- 320px에서는 관점·마지막 한 줄·dialog를 한 열로 쌓고 horizontal page scroll을 만들지 않는다.
- local navigation은 native button tab으로 구현하고 현재 tab을 `aria-selected`로 전달한다.
- 생성·재시도와 tab 변경은 `aria-live="polite"`, 오류는 `role="alert"`로 전달한다.
- 이름 익명화는 시각적 생략뿐 아니라 screen reader용 이름에도 동일하게 적용한다.
- icon-only back, 참가자 명단, dialog close에는 accessible name과 tooltip을 제공한다.

## 9. 검증 시나리오

1. 종료 row에서 들어와 기록이 첫 화면인지 확인한다.
2. 쟁점·관점·변화·남은 질문에 이름이 붙지 않는지 확인한다.
3. 마지막 한 줄과 전체 대화에만 당시 이름이 표시되는지 확인한다.
4. 생성 중에도 전체 대화와 사전 입력으로 이동할 수 있는지 확인한다.
5. 공식 기록 실패 시 방장만 다시 생성할 수 있는지 확인한다.
6. 대화 부족 상태가 실패나 재생성 대상으로 오해되지 않는지 확인한다.
7. 다른 사용자의 `AI_PRIVATE` 원문·존재 여부가 DOM과 접근성 tree에 없는지 확인한다.
8. 참가자 dialog focus 이동·복귀와 keyboard-only tab 전환을 확인한다.
9. 320px와 200% zoom에서 모든 읽기 경로를 사용할 수 있는지 확인한다.

## 10. 인터랙티브 시안 검증 결과

2026-09-02 기준 `discussion-results.html` 시안에서 다음을 확인했다.

- 기록 완성, 생성 중, 참가자 실패, 방장 실패, 대화 부족, 전체 대화와 사전 입력 7개 상태가 독립적으로 전환된다.
- 생성 중에도 전체 대화로 이동할 수 있고, 참가자 실패 화면에는 재시도 control이 존재하지 않는다.
- 방장의 `다시 생성하기` 실행은 공식 기록을 먼저 바꾸지 않고 `다시 정리하고 있어요` 상태로 전환된다.
- 참여자 dialog가 열릴 때 닫기 control로 focus가 이동하고 닫힌 뒤 실행 control로 복귀한다.
- 1200px, 736px과 320px 검증 환경의 실제 content width 273–288px에서 모든 상태와 dialog에 horizontal overflow가 없다.
- icon-only button의 accessible name, tab의 단일 선택 상태, duplicate id 부재를 확인했다.
- 사용자 화면에 `AI_PRIVATE` 내부 용어가 없고 `AI에게만 공개`인 현재 사용자의 항목 하나만 별도 영역에 존재한다.
- 공개 공유·다운로드·내보내기 control과 성공한 기록의 재생성 control이 없다.
