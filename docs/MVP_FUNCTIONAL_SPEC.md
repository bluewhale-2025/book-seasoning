## 0. 문서 목적과 사용 규칙

이 문서는 `PRODUCT_SPEC.md`의 제품 원칙을 실제 화면, 사용자 행동, 권한, 상태, 예외 흐름, 완료 조건으로 구체화한다.

- `PRODUCT_SPEC.md`와 충돌하면 항상 `PRODUCT_SPEC.md`를 우선한다.
- 이 문서가 새로운 제품 행동을 자동으로 확정하지 않는다.
- `결정 필요` 항목은 제품 소유자와 합의하기 전 구현 요구사항이 아니다.
- 합의된 중요한 제품 결정은 이 문서뿐 아니라 `PRODUCT_SPEC.md`에도 반영한다.
- 프레임워크, DB, 인증 공급자, 실시간 통신 기술, LLM 모델 같은 구현 선택은 `docs/TECHNICAL_PLAN.md`와 `docs/DECISIONS.md`에서 다룬다.

### 요구사항 상태

- **확정:** `PRODUCT_SPEC.md`에 근거가 있는 요구사항
- **결정 필요:** 사용자 경험을 바꾸므로 제품 합의가 필요한 항목
- **기술 설계:** 제품 행동은 유지하면서 구현 단계에서 정할 항목
- **MVP 제외:** 현재 제품 기준선에서 명시적으로 제외된 항목

## 1. MVP 목표와 완료 범위

### 1.1 제품 목표 — 확정

완독한 참가자들이 실시간 텍스트로 책을 토론할 때 AI가 좋은 인간 대화를 보존하면서 필요한 순간에만 최소 개입하고, 토론 후 사고의 확장과 잔상을 공동 기록으로 남긴다.

### 1.2 핵심 사용자 여정

1. 참가자가 서비스에 접근한다.
2. 토론 세션에 참가한다.
3. 선택적으로 사전 입력을 작성하고 공개 범위를 지정한다.
4. 방장이 세션을 시작한다.
5. 참가자들이 30분 토론 타이머 동안 실시간 텍스트 토론과 Synthesis를 진행한다.
6. AI가 상태를 관찰하고 필요한 경우에만 개입한다.
7. 각 토론 구간 종료 전에 방장이 15분 연장 또는 마무리를 결정한다. AI는 의견을 제공할 수 있다.
8. AI가 Synthesis를 진행하고 참가자는 선택적으로 마지막 한 줄을 남긴다.
9. 세션이 공식 종료되고 「오늘의 토론 기록」이 확정된다.

### 1.3 MVP 제외 — 확정

- 음성 토론, 음성 인식, speaker diarization
- Full-text RAG
- 세션 간 AI 장기 기억
- 참가자별 AI 성향·변화 분석 리포트
- AI가 선언하는 작품의 단일 정답 또는 최종 해석

## 2. 사용자와 역할

### 2.1 일반 참가자 — 확정

일반 참가자는 다음 행동을 할 수 있어야 한다.

- 선택적 사전 입력 작성
- 각 사전 입력의 `PUBLIC / AI_PRIVATE` 지정
- 실시간 텍스트 채팅 참여
- 현재 의제 확인
- Closing 마지막 한 줄 작성
- 종료 후 「오늘의 토론 기록」 열람
- 연장 세션 계속 참여 또는 자유 퇴장

### 2.2 방장 — 확정

방장은 일반 참가자 권한에 더해 다음 운영 권한을 가진다.

- 세션 시작
- 종료 전 15분 단위 반복 연장 또는 마무리 결정
- 필요 시 `토론 종료`
- 심각한 상황에서 AI 개입 요청
- 최소한의 참가자 관리

방장은 토론 진행 로직을 직접 제어하지 않으며 다음 내부 정보를 볼 수 없어야 한다.

- 참가자별 Discussion Metrics
- `AI_PRIVATE` 원문
- Participant State 내부 추론
- Evaluator·Policy 내부 로그

### 2.3 운영자 — 확정

- 수동으로 `ADMIN` 역할을 부여받은 일반 계정이 운영자 전용 Builder에 접근한다.
- 운영 권한은 Book Context Pack 생성·조사·검수·버전·Publish 관리에 한정된다.
- 운영자도 토론에서는 일반 회원과 같은 권한만 가지며 운영자 여부를 참가자에게 표시하지 않는다.
- 운영자 권한만으로 참가하지 않은 세션 데이터나 다른 사용자의 AI_PRIVATE를 볼 수 없다.
- 세부 권한과 감사 규칙은 §14 `ADMIN-00`을 따른다.

## 3. 사용자 식별, 로그인, 프로필

### ID-01 계정 로그인 — 확정

- 방장과 일반 참가자는 모두 계정 로그인이 필수다.
- 게스트 참가는 MVP에서 제공하지 않는다.
- 계정은 여러 토론의 생성·참여 이력과 결과 접근권을 동일 사용자에게 연결한다.

### ID-02 프로필 이름 — 확정

- 회원가입 시 프로필 이름을 반드시 입력한다.
- 참가자는 계정 프로필에 토론에서 사용할 이름을 설정한다.
- 모든 세션에서 동일한 프로필 이름을 사용하며 세션별 닉네임은 제공하지 않는다.
- 프로필 이름은 다른 사용자와 중복될 수 있다.
- 권한과 데이터 귀속은 프로필 이름이 아니라 불변 계정 ID로 판정한다.
- 사용자는 프로필 이름을 변경할 수 있다.
- 이름 변경은 과거 메시지와 마지막 한 줄의 표시 이름에 소급 적용하지 않는다.
- 변경된 이름은 이후 새로 작성하는 메시지와 새 토론 참여에 적용한다.

### ID-03 최소 프로필과 내 토론 — 확정

- 사용자는 자신의 프로필 이름을 확인하고 설정할 수 있어야 한다.
- 사용자는 자신이 생성했거나 참여한 여러 토론과 종료된 토론 결과를 계정으로 다시 확인하고 관리할 수 있어야 한다.
- MVP에서는 프로필 이미지 업로드를 제공하지 않고 프로필 이름의 첫 글자를 기본 아바타로 사용한다.
- `내 토론`은 `진행 중 / 예정 / 종료` 세 구역으로 나눈다.
- 사용자가 만든 방과 참가한 방을 함께 표시하고 각 방에 `방장 / 참가자` 역할을 표시한다.
- 진행 중인 방을 최상단에 표시한다.
- 예정된 방은 시작 예정 시각이 가까운 순, 종료된 방은 최근 종료 순으로 정렬한다.
- 각 항목에는 방 제목, 책, 진행 상태, 시작 예정 시각, 현재/최대 인원을 표시한다.
- 종료된 항목에서는 읽기 전용 토론방과 「오늘의 토론 기록」으로 이동할 수 있다.

### ID-04 재접속 식별 — 확정 + 기술 설계

참가자가 네트워크 문제나 브라우저 종료 후 로그인된 동일 계정으로 세션에 돌아오면 같은 참가자로 복구되어야 한다. 구체 세션 복구 방식은 기술 설계에서 정한다.

### ID-05 도서관 회원 확인 — 확정

MVP에서는 도서관 회원 여부를 별도로 확인하거나 인증하지 않는다.

### ID-06 로그인 수단과 계정 복구 — 확정

- MVP는 이메일과 비밀번호로 회원가입·로그인한다.
- 회원가입 시 이메일, 비밀번호, 프로필 이름을 필수로 입력한다.
- 이메일은 계정 식별자로 사용하며 중복 가입을 허용하지 않는다. 회원가입 제출 시 중복 여부를 확인하고 이미 사용 중인 이메일이면 계정을 생성하지 않는다.
- 가입 이메일 확인 절차는 제공하지 않으며 이메일 인증 없이 토론을 생성·참가할 수 있다.
- 비밀번호를 잊은 사용자는 가입 시 입력한 이메일을 통해 비밀번호를 재설정할 수 있어야 한다.
- 소셜 로그인은 MVP에서 제공하지 않는다.
- 공개 서비스 전환 시 이메일 확인 필요성을 다시 검토한다.

## 4. 책 탐색과 선택

### BOOK-01 토론 대상 책 — 확정

세션에는 하나의 식별된 책과 운영자가 Publish한 Book Context Pack이 연결되어야 한다. 미공개 Pack은 실제 토론에서 사용할 수 없다.

### BOOK-02 토론방 생성 시 책 선택 — 확정

- 방장은 운영자가 Publish한 Book Context Pack이 있는 책 목록에서 한 권을 선택한다.
- Publish된 Pack이 없는 책은 토론방 생성에 사용할 수 없다.
- 책 제목과 저자로 검색한다.
- 기본 정렬은 최근 추가된 순이며 `최근 추가된 순 / 제목 가나다순 / 저자 가나다순` 정렬을 제공한다.
- 하나의 Published Pack을 하나의 선택 항목으로 표시한다.
- 선택 후 책 기본 정보와 짧은 소개를 확인할 수 있게 한다.
- 검색 결과가 없으면 `아직 토론이 준비된 책이 없습니다`라고 안내한다.
- 사용자가 직접 책을 등록하거나 Pack 생성을 요청하는 기능은 제공하지 않는다.
- Draft, 검수 중, Publish 취소 상태의 Pack은 일반 사용자에게 노출하지 않는다.

### BOOK-03 판본 정보 — 확정

Book Context Pack은 제목, 저자, 출판사, 출간연도, 판본·번역자, ISBN 등을 보존한다. 책 선택 검색 결과에는 표지, 제목, 저자, 출판사, 출간 연도를 표시해 동명 도서와 판본을 구분한다.

### BOOK-04 Pack 지식 구조 — 확정

Published Pack은 짧은 책 소개만 저장하는 카탈로그 항목이 아니라 AI 호스트용 지식 지도여야 한다. 다음 7개 섹션을 표현할 수 있어야 한다.

1. 기본 메타정보
2. 전체 구조와 장·부별 흐름
3. 핵심 주제와 문제의식
4. 주요 인물·개념·사건
5. 주요 장면·주장과 책 안의 위치
6. 토론 가능 쟁점과 관련 근거
7. 해석상 주의사항

각 지식 항목은 `FACT / AUTHOR_STATEMENT / INTERPRETATION / DISCUSSION_SIGNAL` 중 성격, 출처, 출처 Tier, 근거 위치, 정보 부족과 출처 충돌 상태를 보존할 수 있어야 한다. 확인되지 않은 내용을 완성된 사실처럼 채우거나 서로 다른 해석을 하나의 정답으로 합치지 않는다.

### BOOK-05 Book Context Provider — 확정 + 기술 설계

- Evaluator와 AI Host는 Pack 저장 테이블이나 특정 요약 필드에 직접 의존하지 않는다.
- 책 정보는 방에 고정된 정확한 Published Pack 버전을 기준으로 Book Context Provider를 통해 공급한다.
- Provider는 책 정보만 반환하고 참가자 사전 입력이나 세션 대화를 Pack에 병합하지 않는다.
- Retired 버전은 신규 방 검색에서는 숨기되 이미 해당 버전을 고정한 방·세션에서는 계속 사용할 수 있어야 한다.
- Provider의 구체 저장·검색 방식과 AI 호출별 context budget은 기술 문서에서 정한다.

## 5. 세션 생성, 초대, 참가

### SESSION-01 세션 생성 — 확정

- 로그인한 모든 회원은 토론방을 생성할 수 있다.
- 생성자가 자동으로 해당 토론방의 방장이 된다.
- 생성 시 다음 항목을 모두 필수로 입력한다.
  - 방 제목
  - Published Book Context Pack이 연결된 책 한 권
  - 시작 예정 시각
  - 참가 패스워드
  - 최소 참가 인원
  - 최대 참가 인원
- 인원 설정은 `2 ≤ 최소 참가 인원 ≤ 최대 참가 인원 ≤ 15`를 만족해야 한다.
- 방장은 현재 참가 인원과 최소·최대 참가 인원 계산에 포함한다.
- 방장은 생성 후 별도의 방 설정 화면에서 토론방 정보를 관리할 수 있다.

### SESSION-01A 방 설정 변경 — 확정

- 시작 전에는 방 제목, 시작 예정 시각, 참가 패스워드, 최소·최대 참가 인원을 수정할 수 있다.
- 책은 방장 외 다른 참가자가 한 명도 참가 등록하지 않은 경우에만 변경할 수 있다.
- 시작 후에는 방 제목, 책, 시작 예정 시각, 최소 참가 인원을 변경할 수 없다.
- 시작 후에도 참가 패스워드를 변경할 수 있다.
- 패스워드를 변경해도 기존 참가 등록자의 membership과 현재 접속은 유지되며 신규 참가자만 새 패스워드를 입력한다.
- 진행 중 최대 참가 인원은 15명까지 늘릴 수 있다.
- 최대 참가 인원을 줄일 때는 현재 참가 등록 membership 수보다 작게 설정할 수 없다.
- 수정 요청과 신규 참가가 동시에 발생해도 정원 제한이 깨지지 않아야 한다.

### SESSION-02 세션 검색 — 확정

- 로그인한 사용자는 시작 전이거나 진행 중인 토론방을 검색할 수 있어야 한다.
- 방 제목, 책 제목, 저자로 검색할 수 있어야 한다.
- 검색 결과에는 다음 정보를 표시한다.
  - 방 제목
  - 책 표지·제목·저자
  - 방장 프로필 이름
  - 시작 예정 시각
  - 사용자용 진행 상태
  - 현재 참가 인원 / 최대 참가 인원
- 참가자 명단과 방 참가 패스워드는 검색 결과에 표시하지 않는다.
- 진행 중인 방도 공식 종료 전이고 정원이 남아 있으면 검색과 신규 참가가 가능하다.
- 공식 종료된 토론은 전체 검색에서 제외하고 실제 참여자의 `내 토론`에만 표시한다.

### SESSION-02A 사용자용 진행 상태 — 확정

- `시작 예정`: 예정 시각 전이며 아직 시작하지 않음
- `시작 대기`: 예정 시각이 지났지만 방장이 아직 시작하지 않음
- `토론 중`: Opening 또는 Core Discussion 진행 중
- `연장 중`: 승인된 15분 연장 토론 진행 중
- `마무리 중`: Synthesis 또는 Closing 진행 중
- `종료`: 공식 종료됨. 전체 검색에는 표시하지 않음
- `취소됨`: 시작 전에 방장이 취소함. 전체 검색에는 표시하지 않고 등록 이력이 있던 회원의 `내 토론 > 종료`에만 표시
- 참가 가능 여부는 별도 상태인 `참여 가능 / 정원 마감`으로 표시한다.
- Discussion Metrics와 AI 내부 판단은 사용자용 진행 상태에 포함하거나 노출하지 않는다.

### SESSION-03 참가 패스워드 — 확정

- 토론방 참가에는 해당 방의 참가 패스워드가 필요하다.
- 참가 패스워드는 계정 로그인 비밀번호와 구분되어야 한다.
- 참가 패스워드는 4~20자이며 영문 대소문자를 구분하고 숫자·기호를 허용한다.
- 로그인한 사용자가 올바른 참가 패스워드를 입력하면 별도 방장 승인 없이 즉시 참가한다.
- 방장은 시작 전과 진행 중 참가 패스워드를 새 값으로 변경할 수 있다.
- 기존 참가 등록자는 패스워드 변경 이후에도 membership과 재접속 권한을 유지하며 새 패스워드를 다시 입력하지 않는다.
- 잘못된 패스워드에는 `패스워드가 올바르지 않습니다`를 표시하고 입력값을 비운다.
- 반복 오입력은 계정·방 단위로 제한하고 `잠시 후 다시 시도해주세요`를 표시한다. 정확한 기준과 안전한 저장 방식은 기술·보안 설계에서 정한다.
- 정원이 membership 생성 직전에 차면 `방금 정원이 마감되었습니다`를 표시하고 참가시키지 않는다.
- 정원 마감 시 신규 사용자의 입력을 비활성화하고 대기자 명단을 제공하지 않는다.
- 정원이 다시 생기면 검색 결과와 방 상세 상태를 갱신한다.
- 기존 참가 등록자와 실제 참여자는 정원·패스워드 변경과 관계없이 패스워드 없이 재입장한다.
- 방장은 패스워드 입력 없이 자신의 방에 들어간다.
- 반복 참가 요청이 membership이나 정원 점유를 중복 생성하지 않아야 한다.
- 내보내진 사용자에게는 `이 토론방에 다시 참여할 수 없습니다`를 표시한다.
- 취소·종료된 방에는 상태만 안내하고 참가 입력을 제공하지 않는다.
- 참가 패스워드 찾기, 참가 요청, 대기자 명단은 제공하지 않는다.

### SESSION-03A 참가 등록 — 확정

- 검색 결과나 방 상세를 보는 것만으로는 참가 등록되지 않는다.
- 세션 시작 전에 올바른 참가 패스워드를 통과해 대기실에 들어가면 `참가 등록` 상태가 된다.
- 참가 등록은 지속되는 방 membership이며 최대 참가 인원에 포함된다.
- 참가 등록 후 대기실 접속을 종료해도 membership과 정원 점유는 유지된다.
- 참가 등록된 사용자는 `내 토론 > 예정`에서 방을 확인하고 사전 입력을 작성할 수 있다.
- 일반 참가자는 시작 전에 참가를 취소할 수 있다.
- 참가 취소 시 membership, 내 토론 항목, 정원 점유가 제거된다.
- 방장은 생성한 방에서 참가 취소할 수 없으며 해당 방은 항상 내 토론에 유지된다.

### SESSION-04 참가 가능 시점 — 확정

- 세션 시작 전 참가자는 대기실로 들어간다.
- 공식 종료 전에는 Core Discussion, 연장, Synthesis, Closing을 포함한 모든 단계에서 신규 참가를 허용한다.
- 신규 참가는 올바른 참가 패스워드와 최대 인원 미도달 조건을 만족해야 한다.
- 공식 종료 후에는 신규 참가를 허용하지 않는다.
- 늦게 참가한 사용자는 실시간 토론방 입장 전에 현재 단계, 남은 시간, 현재 의제 또는 정리 상태, 현재/최대 인원을 확인한다.
- `마무리 중`이면 현재 토론이 마무리 단계라는 안내를 표시한다.
- 사용자가 `토론에 참여하기`를 선택하면 실시간 토론방에 입장한다.
- 시작 후 신규 참가자에게 사전 입력을 요구하거나 기존 PUBLIC 사전 입력을 진입 화면에 노출하지 않는다.

### SESSION-05 실제 참여 확정 — 확정

- 세션 시작 후 실시간 토론방에 한 번 이상 접속하면 메시지 작성 여부와 관계없이 `실제 참여`로 확정한다.
- 세션 진행 중 처음 참가한 사용자는 토론방 입장 시 참가 등록과 실제 참여가 동시에 확정된다.
- 실제 참여자는 중간에 나가더라도 종료된 토론방과 「오늘의 토론 기록」 열람권을 유지한다.
- 시작 전 등록했지만 진행 중 한 번도 접속하지 않은 일반 참가자는 종료 후 내 토론에서 제거하고 대화·결과 열람권을 부여하지 않는다.
- 방장은 실제 접속 여부와 관계없이 생성한 방과 결과에 대한 관리·열람권을 유지한다.

### SESSION-06 종료된 토론방 재열람 — 확정

- 실제 참여자는 `내 토론 > 종료`에서 종료된 토론방에 다시 들어갈 수 있다.
- 종료된 토론방은 읽기 전용이며 새 메시지, AI 개입, 사전 입력 변경을 허용하지 않는다.
- 참가자는 전체 대화 기록, 책과 세션 정보, 「오늘의 토론 기록」을 열람할 수 있다.
- 종료된 방은 전체 검색에 공개하지 않으며 참여하지 않은 사용자는 열람할 수 없다.

### SESSION-06A 시작 전 토론방 취소 — 확정

- 방장은 세션 시작 전에만 토론방을 취소할 수 있다.
- 취소는 삭제가 아니라 `취소됨` terminal state로 전환한다.
- 취소된 방은 전체 검색에서 즉시 제외한다.
- 모든 참가 등록 membership과 정원 점유를 해제한다.
- 취소 시점에 참가 등록되어 있던 회원의 `내 토론 > 종료`에는 `취소됨` 항목을 남긴다.
- 취소된 항목은 방 상세로 진입할 수 없으며 사전 입력, 대화, 결과를 열람하거나 변경할 수 없다.
- 세션 시작 후에는 취소할 수 없고 `토론 종료` 흐름을 사용한다.

### SESSION-07 참가자 관리 — 확정

- 방장은 시작 전 대기실과 진행 중 토론에서 참가자를 내보낼 수 있다.
- 내보내기 전 대상 참가자의 프로필 이름과 영향을 보여주는 확인 절차를 둔다.
- 내보내진 참가자는 해당 방에 다시 참가할 수 없다.
- 내보낸 참가자의 기존 메시지와 Raw Data는 보존한다.
- 내보낸 참가자는 해당 방, 종료된 대화, 「오늘의 토론 기록」 열람권을 잃는다.
- 내보내기 시 membership과 정원 점유를 해제한다.
- 시작 전에는 참가 등록된 회원에게 방장 권한을 이전할 수 있다.
- 시작 후에는 실제 참여자에게 방장 권한을 이전할 수 있다.
- 권한 이전 후 기존 방장은 일반 참가자가 되며 방에는 항상 한 명의 방장만 존재한다.
- 공동 방장과 일반 참가자 신고·차단 기능은 MVP에서 제외한다.

## 6. 사전 입력

### PREP-01 입력 선택성 — 확정

사전 입력은 선택사항이며 작성하지 않아도 세션 참가나 발언이 제한되지 않아야 한다.

### PREP-02 입력 항목 — 확정

참가자는 다음 항목을 작성할 수 있다.

1. 좋아했던 문장과 그 문장에서 파생된 자신의 생각
2. 가장 인상 깊었던 장면·주장·부분
3. 다른 사람들과 이야기하고 싶은 질문

### PREP-03 항목별 공개 범위 — 확정

각 항목은 독립적으로 `PUBLIC / AI_PRIVATE`를 선택할 수 있어야 한다.

- `PUBLIC`: 참가자에게 공개 가능하며 AI가 작성자의 발언과 직접 연결할 수 있다.
- `AI_PRIVATE`: 내부 의제·평가에 사용할 수 있지만 원문, 표현, 출처, 작성자를 참가자에게 직접 또는 추론 가능하게 노출할 수 없다.

### PREP-04 작성·수정 가능 시점 — 확정

- 참가 등록 후 대기실에서 작성한다.
- 세션 시작 전까지 작성·수정·삭제와 항목별 공개 범위 변경이 가능하다.
- 세션 시작과 동시에 모든 사전 입력과 공개 범위를 잠그고 이후 변경을 허용하지 않는다.
- 시작 후 신규 참가자는 사전 입력을 작성하지 않는다.

### PREP-05 참가자 간 공개 시점 — 확정

- `PUBLIC` 항목은 시작 전 대기실에서 참가 등록 회원에게 작성자의 프로필 이름과 함께 표시한다.
- 실시간 토론 중에는 사전 입력 전용 패널을 노출하지 않는다.
- 종료된 토론방에서는 당시 `PUBLIC` 항목을 실제 참여자가 읽기 전용으로 열람할 수 있다.
- `AI_PRIVATE`는 작성자 본인과 허용된 AI 내부 처리 경로 외에는 어떤 단계에서도 표시하지 않는다.

## 7. 대기실과 세션 시작

### WAIT-01 대기실 — 확정

- 방 제목, 책 표지·제목·저자, 시작 예정 시각과 현재 상태를 표시한다.
- `현재 등록 인원 / 최대 인원`과 `현재 접속 인원 / 최소 시작 인원`을 구분해 표시한다.
- 등록 참가자의 프로필 이름, 방장 여부, `접속 중 / 오프라인` 상태를 보여준다.
- PUBLIC 사전 입력은 작성자 이름과 함께 등록 참가자에게 표시한다.
- AI_PRIVATE는 작성자 본인에게만 표시한다.
- 사전 입력 완료 여부를 참가자별 배지로 공개하지 않는다.
- 일반 참가자는 자신의 사전 입력을 관리하고 시작 전 참가 등록을 취소할 수 있다.
- 방장에게만 시작 버튼을 보여주고 예정 시각·최소 접속 인원 조건을 만족하지 않으면 비활성화 사유를 표시한다.
- 참가 패스워드는 대기실의 일반 참가자에게 표시하지 않는다.

### WAIT-02 시작 권한 — 확정

방장만 세션을 시작할 수 있어야 한다.

### WAIT-03 시작 조건 — 확정

- 최소 시작 인원은 방장이 시작을 시도하는 시점에 대기실에 실제 접속 중인 참가 등록 회원 수로 계산한다.
- 대기실 접속 인원이 방장이 설정한 최소 참가 인원보다 적으면 방장은 세션을 시작할 수 없다.
- 등록했지만 현재 대기실에 접속하지 않은 일반 참가자는 최대 정원에는 포함되지만 최소 시작 인원에는 포함되지 않는다.
- 방장은 최소 시작 인원과 최대 참가 인원 계산에 모두 포함한다.
- 대기실은 참가 등록 수와 현재 접속 수를 구분하고 `현재 접속 n명 / 시작 최소 m명`을 보여줘야 한다.
- 방장은 시작 예정 시각 이전에 세션을 시작할 수 없다.
- 시작 예정 시각 이후이고 최소 인원이 충족되면 방장이 수동으로 세션을 시작할 수 있다.
- 최소 인원이 충족되면 늦은 참가자를 기다리지 않고 시작할 수 있다.

## 8. 실시간 토론방

### CHAT-01 실시간 텍스트 메시지 — 확정

- 모든 메시지는 작성자를 식별할 수 있어야 한다.
- 참가자 메시지와 AI Host 발언은 명확히 구분되어야 한다.
- 현재 의제를 지속적으로 확인할 수 있어야 한다.
- 좋은 인간 대화가 진행 중일 때 AI가 나타나지 않는 상태가 정상이어야 한다.
- 텍스트 메시지만 지원하고 메시지 한 개는 최대 2,000자다.
- 여러 줄 입력을 지원하며 작성자와 작성 시각을 표시한다.

### CHAT-02 메시지 순서와 전달 상태 — 확정 + 기술 설계

- 메시지 전송 중, 전송 실패, 재시도 상태를 표시한다.
- 재시도해도 같은 메시지가 서버에서 중복 확정되지 않아야 한다.
- 서버 확정 순서와 실시간 표시의 구체 일관성 방식은 기술 설계에서 정한다.

### CHAT-03 메시지 수정·삭제 — 확정

- 서버에서 전송이 확정된 메시지는 참가자가 수정하거나 삭제할 수 없다.
- 메시지는 변경되지 않는 Raw Data로 보존한다.

### CHAT-04 답장과 반응 — 확정

- 원본 메시지 reference와 짧은 인용을 표시하는 inline reply를 지원한다.
- 별도 thread는 사용하지 않는다.
- emoji reaction은 MVP에서 제외한다.

### CHAT-04A 첨부 — MVP 제외

- 이미지 첨부
- 파일 첨부
- 음성 첨부

### CHAT-05 typing과 presence — 확정

- 대기실에는 등록 참가자의 프로필 이름, 방장 표시, `접속 중 / 오프라인` 상태를 보여준다.
- 토론 중에는 상단에 현재 접속 인원을 표시하고 참가자 목록은 펼쳐서 확인할 수 있게 한다.
- 토론 중 참가자 목록에는 프로필 이름, 방장 여부, 단순 접속 상태만 표시한다.
- 메시지를 작성 중인 참가자는 `프로필 이름 + 입력 중`으로 표시한다.
- 마지막 접속 시각, 발언량, 침묵 여부, 활동 점수와 내부 Discussion Metrics는 노출하지 않는다.
- 화면을 나가거나 연결이 끊겨도 참가 등록과 실제 참여 기록은 유지한다.
- AI는 presence, typing, 참가 시각을 내부 판단 신호로 사용할 수 있으나 참가자 평가값으로 노출하지 않는다.

### CHAT-06 중도 퇴장·재접속 — 확정

- 브라우저를 닫거나 다른 화면으로 이동하는 것은 일시 접속 종료이며 참가 등록이나 실제 참여를 취소하지 않는다.
- 토론 중 `나가기`를 누르면 공식 종료 전까지 다시 들어올 수 있다는 확인창을 보여주고 현재 화면에서만 나간다.
- 세션 시작 후 참가자는 자신의 참여 기록을 완전히 철회하거나 정원 점유를 해제할 수 없다.
- 실제 참여자는 공식 종료 전까지 동일 계정으로 언제든 재접속할 수 있다.
- 재접속 시 놓친 메시지, 현재 의제·단계, 남은 시간, 참가자 상태를 동기화한 뒤 입력을 허용한다.
- 연결 복구 중에는 `연결 복구 중` 상태를 표시하고 메시지 입력을 비활성화한다.
- AI는 연결이 끊긴 참가자를 침묵 중인 사람으로 판단하거나 발언을 요청하지 않는다.
- 세션 종료 시 오프라인이어도 실제 참여자는 `내 토론 > 종료`에서 기록과 결과를 열람할 수 있다.
- 중도 이탈 횟수와 접속 시간은 다른 참가자에게 공개하지 않는다.

## 9. AI 호스트 개입

### AI-01 최소 필요 개입 — 확정

AI는 개입 가치가 인간 대화를 끊는 비용보다 클 때만 개입해야 하며, 좋은 흐름에서는 `WAIT`를 선택해야 한다.

### AI-02 한 판단 주기의 단일 목표 — 확정

Evaluator가 여러 문제를 발견하더라도 Policy는 원칙적으로 가장 필요한 한 가지 행동 목표만 선택해야 한다.

### AI-03 행동 후보 — 확정

- `WAIT`
- `DEEPEN`
- `EXPAND`
- `RECONNECT`
- `RECONNECT_TO_BOOK`
- `RECONNECT_AND_REFLECT`
- `INVITE`
- `REVIVE`
- `SUMMARIZE`
- `TRANSITION`
- `RECOMMEND_EXTENSION`

### AI-04 방장의 AI 개입 요청 — 확정

- 방장에게만 `AI 도움 요청` 버튼을 제공한다.
- Opening, 본 토론, 연장 중에만 사용할 수 있고 Synthesis와 Closing에서는 사용할 수 없다.
- 요청 사유는 `대화가 멈춤 / 논의가 반복되거나 막힘 / 주제에서 너무 벗어남 / 갈등으로 흐름 정리가 필요함` 중 하나를 선택한다.
- 방장이 AI에 지시문을 쓰는 자유 입력란은 제공하지 않는다.
- 요청이 접수되면 AI는 최근 대화와 선택 사유를 확인하고 한 번의 개입 메시지를 반드시 작성한다.
- 방장은 구체적인 질문이나 결론을 지정할 수 없으며 개입 목표와 내용은 AI가 판단한다.
- 요청으로 생성된 메시지에 `방장 요청으로 개입` 표시를 붙여 자동 개입과 구분한다.
- 처리 중에는 중복 요청을 막으며 추가 요청 제한 시간은 기술 설계 또는 실험값으로 정한다.
- AI 요청이나 생성 실패가 인간 대화와 세션 진행을 막아서는 안 된다.
- 심각한 참가자 문제는 AI 요청만으로 처리하지 않고 방장의 참가자 내보내기 권한을 사용한다.

### AI-05 실패·지연 상태 — 확정

- 자동 평가와 자동 개입에는 참가자-facing `AI가 생각 중` 표시를 하지 않는다.
- 자동 평가나 개입이 실패해도 인간 대화는 그대로 계속된다.
- 방장의 `AI 도움 요청` 처리 상태는 방장에게만 `AI가 흐름을 확인 중`으로 표시한다.
- 방장 요청이 실패하면 방장에게만 재시도 안내를 보여준다.
- Opening과 Synthesis의 AI 발언이 지연되면 모든 참가자에게 `AI 응답 준비 중` 상태를 표시하되 채팅은 허용한다.
- Opening 생성이 최종 실패하면 미리 준비된 기본 시작 질문으로 토론을 시작한다.
- Synthesis 생성이 최종 실패하면 안내 후 Closing으로 넘어간다.
- 연장에 대한 AI 의견 생성이 최종 실패해도 방장의 연장·마무리 선택은 그대로 제공한다.
- 최종 토론 기록 생성이 지연되거나 실패해도 세션은 정상 종료하며 결과 화면에 `생성 중 / 재시도 중` 상태를 표시한다.
- 원본 오류, 모델명, 내부 점수는 사용자에게 공개하지 않는다.
- 자동 재시도 횟수와 지연 표시 기준은 기술 설계에서 정한다.
- 재시도로 AI 메시지나 결과물이 중복 생성되지 않아야 한다.

### AI-06 내부 정보 비노출 — 확정

AI Host 출력에는 내부 점수, Participant State 추론, `AI_PRIVATE` 원문이나 작성자를 노출할 수 없다.

### AI-07 Living Wiki 역할과 구성 — 확정

- Living Wiki는 참가자에게 보여주는 공동 문서가 아니라 Evaluator와 Host의 세션 내부 작업 기억이다.
- Raw Data는 변경되지 않는 사실 원본이고 Living Wiki는 원본을 근거로 갱신되는 구조화된 해석이다.
- Living Wiki는 Current Topic, Perspective Map, Book Grounding, Issue & Question Map, Coverage, 공개 근거 기반 Participant State, Discussion Metrics & Key Changes를 유지한다.
- 참가자 사전 입력과 세션 대화 원문은 Wiki에 병합해 원본을 대체하지 않는다.
- 서로 충돌하는 관점은 각각의 근거와 관계를 유지하며 거짓 합의로 평탄화하지 않는다.
- 참가자의 공개 발언 변화를 기록할 수는 있지만 내적 생각이 바뀌었다고 단정하지 않는다.

### AI-08 Living Wiki 근거와 버전 — 확정 + 기술 설계

- 가능한 Wiki 항목에는 메시지, PUBLIC 사전 입력, AI 개입 또는 Book Context 항목의 원본 reference를 붙인다.
- PUBLIC-lane Wiki에는 `AI_PRIVATE` 원문, private reference 또는 작성자를 추론할 수 있는 내용을 넣을 수 없다.
- 의미 있는 대화 묶음이 평가될 때 Wiki와 Discussion Metrics를 같은 분석 주기에서 갱신한다.
- 각 버전은 어느 메시지까지 반영했는지 기준점을 가진다.
- 오래된 동시 작업이 최신 Wiki를 덮어쓰지 않아야 한다.
- Wiki 갱신 실패 시 마지막 확정 버전을 유지하고 인간 토론을 계속한다.

### AI-09 Topic Checkpoint와 Final Wiki — 확정

- 새 대화가 없는 침묵·시간 이벤트에서는 기존 Wiki로 상태만 평가할 수 있으며 불필요한 전체 재작성을 하지 않는다.
- 주제 전환 시 관련 Raw Data와 Wiki를 다시 대조해 Topic Checkpoint를 만든다.
- 세션 종료 시 필요한 Raw Data를 다시 조회하고 정합성을 검증해 Final Wiki를 확정한다.
- Final Wiki는 다음 세션의 AI 컨텍스트로 자동 승계하지 않는다.
- Final Wiki는 공식 토론 기록의 입력이 될 수 있지만 참가자-facing 공식 기록과 동일한 데이터는 아니다.
- 공식 종료 후 Final Wiki와 성공한 공식 기록은 AI 재실행으로 임의 변경하지 않는다.

### AI-10 Raw Data 재확인 — 확정 + 기술 설계

- Wiki만으로 모호한 판단, 이전 입장·근거, 중복 의제, 관점 변화, 사전 입력 연결, Wiki 충돌을 확인해야 할 때 원본을 다시 조회할 수 있어야 한다.
- 검색 결과의 요약만 사용하지 않고 연결된 원본 메시지와 필요한 주변 문맥을 함께 확인한다.
- 원본은 개별 메시지 단위로 보존하고 검색용 대화 묶음은 파생 데이터로만 취급한다.
- PUBLIC과 AI_PRIVATE를 같은 검색 단위나 같은 context 경로에 섞지 않는다.
- 직접 조회, metadata 검색, 대화 묶음 검색의 구체 구현은 기술 설계에서 정한다.

## 10. 시간, 연장, 종료

### TIME-01 기본 시간 — 확정

- 기본 토론 타이머는 30분이며 Opening, Core Discussion, Synthesis를 포함한다.
- 토론 타이머 종료 후 Closing을 최대 5분 별도로 진행한다.
- 연장이 없으면 세션 생성부터 공식 종료까지 최대 약 35분이다.
- 타이머는 서버 시각을 기준으로 하고 모든 참가자에게 계속 표시한다.

### TIME-02 종료 임박 표시 — 확정

- 기본·연장 토론 타이머가 7분 남으면 모든 참가자에게 종료 임박 상태와 AI 의견을 표시한다.
- 방장에게 2분 동안 `15분 연장 / 마무리하기` 버튼을 제공한다.
- 일반 참가자는 결정 버튼을 사용할 수 없다.

### TIME-03 연장 결정 — 확정

- 각 기본·연장 토론 구간의 남은 시간이 7분일 때 방장에게 `15분 연장 / 마무리하기`를 묻는다.
- AI는 현재 흐름을 바탕으로 `연장 추천 / 마무리 추천` 의견을 함께 제공할 수 있다.
- 방장은 AI 의견과 관계없이 연장을 선택할 수 있다.
- 방장만 결정 버튼을 사용할 수 있고, 추천과 결정 결과는 모든 참가자에게 표시한다.
- 방장이 마무리를 선택하면 즉시 Synthesis로 전환한다.
- 남은 시간이 5분이 될 때까지 응답하지 않으면 자동으로 Synthesis에 들어간다.
- 연장을 선택하면 즉시 토론 타이머를 15분 늘리고 `연장 중`으로 전환한다.
- 방장이 오프라인이고 권한 이전도 없으면 응답 없음으로 처리한다.
- AI 의견 생성 실패는 방장의 선택을 막지 않는다.
- 연장 타이머가 다시 7분 남으면 같은 절차를 반복한다.

### TIME-04 반복 연장 — 확정

- 연장은 한 번에 15분이며 횟수 제한 없이 반복할 수 있다.
- 자동 연장은 없고 매 연장 구간 종료 전에 방장이 다시 명시적으로 결정한다.
- 승인하면 상태를 `연장 중`으로 바꾸고 변경된 종료 시각을 모든 참가자에게 알린다.
- 연장 중에도 신규 참가와 재접속을 허용한다.
- 일반 참가자 투표와 자동 다수결은 제공하지 않는다.
- 방장은 연장 중에도 `토론 종료`를 실행할 수 있다.

### TIME-05 방장의 토론 종료 — 확정

- 세션 시작 후 방장만 언제든 `토론 종료`를 실행할 수 있다. 시작 전에는 토론방 취소를 사용한다.
- 실행 전 모든 참가자의 입력이 종료되고 같은 세션을 다시 시작할 수 없다는 확인창을 보여준다.
- 종료 사유 입력과 참가자 투표는 제공하지 않는다.
- 확정 즉시 신규 참가, 재접속, 메시지 전송, 연장 결정을 막는다.
- 종료 전에 서버에서 확정된 메시지는 보존하고 처리 중이던 미확정 메시지는 전송 실패로 처리한다.
- 모든 참가자에게 `방장이 토론을 종료했습니다`를 알리고 상태를 `종료`로 전환한다.
- 종료는 취소할 수 없고 같은 세션을 다시 열 수 없다.
- Core Discussion 또는 연장 중 종료하면 실시간 Synthesis와 Closing을 생략한다.
- Synthesis 또는 Closing 중 종료하면 그 시점까지 확정된 입력만 사용한다.
- 종료 시점까지의 Raw Data로 「오늘의 토론 기록」을 비동기로 생성한다.
- 대화가 충분하지 않으면 내용을 생성해 채우지 않고 `기록을 만들기에 충분한 대화가 없습니다`라고 표시한다.
- 이미 확정된 마지막 한 줄은 결과에 포함하고 미작성자에게 추가 입력을 요구하지 않는다.
- 실제 참여자는 일반 종료와 동일한 종료 후 열람권을 가진다.
- 결과 생성 실패는 종료를 되돌리지 않으며 결과 화면에 생성·재시도 상태를 표시한다.

## 11. Synthesis와 Closing

### CLOSE-01 Synthesis — 확정

AI는 다음 순서로 토론을 정리해야 한다.

1. 주요 관점 2~4개와 갈린 지점 정리
2. 불일치를 거짓 합의로 만들지 않음
3. 짧은 reflection 요청
4. 책 밖으로 많이 확장됐다면 책으로 마지막 재접속

AI는 작품의 정답이나 최종 해석을 선언할 수 없다.

### CLOSE-02 마지막 한 줄 — 확정

참가자는 선택적으로 마지막 한 줄을 남길 수 있다. Synthesis에서 이미 충분한 reflection을 남겼다면 중복 입력을 강요하지 않는다.

- 실제 참여자별 하나, 최대 300자다.
- `건너뛰기`를 선택할 수 있다.
- Closing 종료 전까지 자신의 입력을 수정하거나 삭제할 수 있다.
- 다른 참가자의 마지막 한 줄은 Closing 중 공개하지 않는다.
- 결과에는 제출 당시 프로필 이름과 함께 표시하고 이후 프로필 이름 변경으로 과거 기록을 바꾸지 않는다.
- 제출하지 않은 참가자는 결과에 표시하지 않는다.

### CLOSE-03 Closing 입력 종료 조건 — 확정

- Closing은 최대 5분 동안 진행한다.
- 일반 채팅 입력은 닫고 기존 대화는 읽을 수 있게 한다.
- 현재 접속 중인 실제 참여자 전원이 제출 또는 건너뛰기를 선택하면 5분 전에도 공식 종료할 수 있다.
- 응답하지 않거나 오프라인인 참가자가 있어도 5분이 지나면 자동 종료한다.
- 방장은 일반 종료 흐름에서 Closing만 임의로 조기 마감할 수 없다. 긴급한 경우 `토론 종료`를 사용한다.
- Closing 도중 재접속하거나 신규 참가한 실제 참여자도 남은 시간 안에 제출할 수 있지만 마감 시각은 늘어나지 않는다.
- 서버가 마감 전에 확정한 입력만 결과에 포함한다.
- 공식 종료 후 마지막 한 줄을 수정하거나 삭제할 수 없다.
- Closing에서는 AI Evaluator와 자동 개입을 중지하고 새로운 질문이나 주제를 만들지 않는다.

### CLOSE-04 공식 종료 — 확정

세션이 공식 종료되면 Final Wiki와 공식 토론 기록은 확정되고 이후 대화나 개인 메모로 변경되지 않아야 한다.

## 12. 「오늘의 토론 기록」

### RECORD-01 생성 기준 — 확정

기록은 준비된 Agenda가 아니라 실제로 의미 있게 다뤄진 내용을 기준으로 생성한다.

### RECORD-02 구성 — 확정

- 오늘의 핵심 쟁점 약 2~4개
- 관점 지도: 주요 관점, 충돌, 연결, 제3의 시각
- 오늘 생긴 변화와 확장
- 남은 질문

### RECORD-03 익명화 — 확정

- 핵심 쟁점·관점·변화·남은 질문에는 기본적으로 참가자 이름을 붙이지 않는다.
- 참가자가 직접 작성한 마지막 한 줄은 이름과 함께 표시할 수 있다.
- 근거가 부족한 내적 생각 변화를 단정하지 않는다.

### RECORD-04 열람 권한과 기간 — 확정

- 방장과 세션에 실제 참여한 계정만 종료된 토론방과 「오늘의 토론 기록」을 열람할 수 있다.
- 참가 등록만 하고 실시간 토론방에 들어오지 않은 일반 참가자는 열람할 수 없다.
- 세션 도중 화면을 나갔거나 종료 순간 오프라인이어도 실제 참여 이력이 있으면 열람할 수 있다.
- 방장이 내보낸 참가자는 자신의 과거 메시지가 보존되어도 종료된 방과 결과를 열람할 수 없다.
- 종료된 방에서는 방·책 정보, 실제 참여자 목록, 전체 채팅과 AI 발언, PUBLIC 사전 입력, 「오늘의 토론 기록」, 마지막 한 줄을 읽기 전용으로 제공한다.
- AI_PRIVATE 사전 입력은 작성자 본인에게만 다시 보여준다.
- 내부 AI 평가·Discussion Metrics·운영 로그는 공개하지 않는다.
- 종료 후 참가자와 방장은 메시지, 사전 입력, 마지막 한 줄, 공식 기록을 수정하거나 삭제할 수 없다.
- 방장도 새로운 열람자를 추가하거나 권한을 부여할 수 없다.
- 공개 공유 링크, 비회원 공개, SNS 공유, 파일 다운로드·내보내기는 MVP에서 제외한다.
- 종료된 방은 전체 검색에서 제외하고 `내 토론 > 종료`에서만 접근한다.
- 별도 자동 만료 기간은 두지 않고 데이터 보관·탈퇴·삭제 정책에 따라 유지한다.

### RECORD-05 생성 실패와 재시도 — 확정

- 결과 생성 중에도 종료된 채팅을 먼저 열람할 수 있다.
- 결과 영역에 `생성 중 / 재시도 중` 상태를 표시한다.
- 생성 실패는 세션의 공식 종료와 열람 가능한 원본 대화를 되돌리지 않는다.
- 최초 공식 결과가 성공적으로 확정되기 전에는 자동 재시도할 수 있다.
- 공식 결과가 확정된 뒤에는 임의로 계속 재생성하거나 변경하지 않는다.
- 재시도 횟수와 운영자 복구 방식은 기술·운영 설계에서 정한다.

## 14. Book Context Builder와 운영자 검수

### ADMIN-00 운영자 계정과 권한 — 확정

- 모든 계정은 기본적으로 일반 회원이며 지정된 계정만 `ADMIN` 역할을 가진다.
- 운영자 지정·해제는 배포 환경 또는 관리 명령으로 수동 처리한다.
- 운영자 회원가입·초대·역할 관리 UI는 제공하지 않는다.
- 운영자는 일반 로그인 후 운영자 전용 Builder 화면을 사용한다.
- 운영자 화면과 API는 서버 권한 검사로 보호한다.
- 운영자는 Pack 초안 생성, 조사 상태 확인·재시도, 검수, 항목 수정·삭제·재생성, 상태 변경, Publish, Publish 취소와 버전 관리를 수행할 수 있다.
- 편집자·검수자·게시자 역할은 별도로 나누지 않는다.
- 운영자 계정도 일반 회원처럼 토론방을 생성·참가할 수 있지만 해당 토론에서는 일반 회원과 같은 권한만 가진다.
- 운영자 여부는 참가자에게 표시하지 않는다.
- 운영자 권한만으로 참가하지 않은 토론방의 채팅, 사전 입력, 결과를 볼 수 없다.
- 다른 사용자의 AI_PRIVATE 입력은 운영자에게도 기본적으로 공개하지 않는다.
- 회원 비밀번호 열람, 사용자 사칭, 회원 관리, 신고 처리, 메시지 삭제, 세션 강제 개입은 운영자 도구 범위에서 제외한다.
- Pack 관련 운영자 동작에는 실행 계정, 시각, 대상, 변경 내용을 감사 로그로 남긴다.

### ADMIN-01 Builder 입력 — 확정

운영자는 책 제목과 저자를 입력해 Book Context Pack 초안 생성을 시작할 수 있어야 한다.

### ADMIN-02 자동 조사와 분류 — 확정

Builder는 공개 자료를 조사하고 다음을 구분해야 한다.

- 출처 Tier A~E
- `FACT`
- `AUTHOR_STATEMENT`
- `INTERPRETATION`
- `DISCUSSION_SIGNAL`
- 정보 부족
- 출처 충돌

Builder는 출처 등급 하나를 기계적인 정확도 점수로 사용하지 않는다. FACT는 공식·고신뢰 출처 또는 복수 출처 교차확인을 우선하고, AUTHOR_STATEMENT는 저자의 직접 발언 원출처를 우선하며, INTERPRETATION은 서로 다른 해석과 각각의 출처를 병렬로 보존한다. Tier D~E 자료는 토론 신호 탐색에는 사용할 수 있지만 사실의 단독 근거로 사용하지 않는다.

### ADMIN-03 Pack 검수 — 확정

운영자는 7개 Pack 섹션과 항목별 성격·출처·근거 위치·정보 부족·충돌 상태를 확인하고 수정, 삭제, 재생성할 수 있어야 한다. 자동 재생성 결과가 기존 운영자 수정을 바로 덮어쓰면 안 되며 반영 전 변경 영향을 확인할 수 있어야 한다.

### ADMIN-04 Publish Gate — 확정

- 상태 흐름은 Draft → Review → Published의 의미를 가져야 한다.
- 운영자가 명시적으로 Publish하기 전 실제 토론에서 사용할 수 없다.
- 책 식별, 핵심 FACT 충돌, 7개 섹션 Coverage, 출처 품질, 불확실성을 확인할 수 있어야 한다.
- Coverage가 부족하더라도 확인되지 않은 내용을 억지로 채워 통과시켜서는 안 된다. Publish가 허용되는 부족 상태와 차단되는 핵심 결함은 운영자에게 명시적으로 보여야 한다.
- 출처 충돌을 숨기거나 한쪽을 임의로 사실화한 상태로 Publish할 수 없어야 한다.

### ADMIN-05 Pack 버전과 운영자 UX — 확정

- Pack 상태는 `Draft → Review → Published → Retired`다.
- Draft만 수정할 수 있고 Review에서 수정이 필요하면 Draft로 되돌린다.
- Published 버전을 덮어쓰지 않고 수정 시 새 Draft 버전을 만든다.
- 책별 버전을 `v1, v2, v3...`처럼 증가시킨다.
- 한 책에는 신규 방용 활성 Published 버전을 하나만 둔다.
- 새 버전 Publish 시 기존 활성 버전은 Retired가 된다.
- 방 생성 시 정확한 Pack 버전을 고정하고 이후 버전 변화로 기존 방·세션·결과를 변경하지 않는다.
- Publish 취소는 Retired 전환이며 신규 책 선택 목록에서 즉시 숨긴다.
- Retired 버전을 참조하는 기존 방은 계속 해당 버전을 사용할 수 있다.
- 기존 방까지 중단하는 긴급 폐기 기능은 MVP에서 제외한다.
- 활성 Published 버전이 없으면 해당 책은 신규 방 목록에서 사라진다.
- Draft는 자동 저장하고 저장 상태를 표시한다.
- 전체·항목별 재생성은 Draft 반영 전 영향을 확인받는다.
- Publish와 Publish 취소에는 확인 절차가 필요하고 Publish 취소 사유는 필수다.
- 삭제 대신 Retired 상태와 변경 이력을 감사 로그에 보존한다.
- 조사 작업의 진행률·실패·재시도 상태를 표시한다.

## 15. 개인정보, 데이터 보관, 삭제

### PRIV-01 AI_PRIVATE 불변 규칙 — 확정

`AI_PRIVATE` 원문, 표현, 출처, 작성자 또는 작성자를 추론할 수 있는 정보는 다른 참가자에게 노출할 수 없다. 이 규칙은 threshold나 weight로 완화할 수 없다.

### PRIV-02 Raw Data — 확정

Raw Data는 사실의 source of truth이며 AI가 임의로 수정한 것으로 취급할 수 없다.

### PRIV-03 데이터 보관 기간 — 확정

- 활성 계정과 프로필은 탈퇴할 때까지 보관한다.
- 원본 채팅, PUBLIC 사전 입력, Final Wiki와 공식 토론 기록은 자동 만료 없이 보관한다.
- AI_PRIVATE는 작성자 탈퇴 또는 운영 삭제 시까지 보관한다.
- AI 평가·Policy·Host 진단 로그는 세션 종료 후 90일간 보관하고 이후 삭제하거나 비식별 집계만 남긴다.
- Book Context 조사 원본·출처·Published·Retired 버전과 운영자 감사 로그는 자동 만료 없이 보관한다.
- 백업의 최종 삭제 시점과 운영 삭제 절차는 기술·보안 설계에서 정한다.
- 공개 서비스 전 적용 지역의 개인정보·보존 의무를 별도 검토한다.

### PRIV-04 탈퇴·삭제 요청 — 확정

- 사용자는 프로필 설정에서 현재 비밀번호와 영향을 확인한 뒤 탈퇴할 수 있다.
- 진행 중인 토론의 실제 참여자는 종료 전 탈퇴할 수 없다.
- 예정된 방의 방장은 권한 이전 또는 방 취소 후 탈퇴할 수 있다.
- 일반 참가자의 시작 전 membership은 탈퇴 시 자동 취소한다.
- ADMIN은 역할을 수동 해제한 뒤 탈퇴할 수 있다.
- 탈퇴는 복구할 수 없으며 완료 후 같은 이메일로 새 계정을 만들 수 있다.
- 이메일, 비밀번호 정보, 현재 프로필 이름, 계정 설정, AI_PRIVATE를 삭제한다.
- 공동 채팅·PUBLIC 사전 입력·마지막 한 줄 내용은 유지하고 작성자를 `탈퇴한 사용자`로 익명화한다.
- 내부에는 공동 기록 연결용 비식별 식별자만 남긴다.
- 이미 확정된 익명 공동 기록은 유지한다.
- 탈퇴 익명화는 공식 기록 불변 원칙의 개인정보 예외다.
- 개별 메시지 직접 삭제 기능은 제공하지 않는다.
- 개인정보·법적 문제의 개별 삭제는 별도 운영 요청으로 처리하고 삭제 표식을 남긴다.
- 전체 데이터 내보내기는 MVP에서 제공하지 않는다.

## 16. 운영 예외와 복구

### ERROR-01 네트워크 단절 — 확정

- `연결됨 / 재연결 중 / 오프라인` 상태를 구분한다.
- 단절 중에는 기존 대화만 읽을 수 있고 메시지·운영 버튼은 비활성화한다.
- 작성 중인 입력은 브라우저에 유지한다.
- 재연결 후 누락 메시지, 단계, 남은 시간, 역할, 참가자 상태를 동기화한 뒤 입력을 허용한다.
- 충돌 시 서버 상태를 우선한다.
- 개인·서버 연결 단절 중에도 타이머는 계속 흐르고 이후 반복 연장으로 보충할 수 있다.

### ERROR-02 서버 또는 AI 장애 — 확정

- 미확정 메시지는 확정 메시지처럼 표시하지 않고 실패 시 내용을 유지해 다시 보내기를 제공한다.
- 시작, 권한 이전, 내보내기, 연장, 종료는 서버 성공 확인 후 화면에 반영한다.
- 운영 명령 실패 시 기존 상태를 유지하고 재시도를 안내한다.
- 자동 AI 실패는 인간 대화를 막지 않는다.
- Opening은 기본 질문, Synthesis는 Closing 전환, 연장 AI 의견은 방장 직접 결정으로 대체한다.
- 결과 생성은 세션 종료와 분리하고 자동 재시도 상태를 표시한다.
- 자동 재시도 소진 시 `토론 기록을 만들지 못했습니다`를 표시하고 방장에게만 `다시 생성하기`를 제공한다.
- 최초 공식 결과 확정 전만 재시도하며 성공한 결과는 다시 생성하지 않는다.
- Builder 실패는 Draft를 보존하고 실패 단계·재시도 가능 여부를 표시하며 자동 Publish하지 않는다.
- 원본 오류, 모델명, stack trace, 내부 점수는 사용자에게 노출하지 않는다.
- 장애 로그는 데이터 내용이 아닌 작업 상태 중심으로 기록한다.
- 전체 재해복구는 기술·인프라 계획에서 정한다.

### ERROR-03 중복 명령 — 확정 + 기술 설계

- 메시지와 세션 시작, 방장 이전, 내보내기, 연장, 토론 종료, Final Wiki 확정이 중복 요청되어도 한 번만 반영한다.
- 구체 idempotency와 concurrency 방식은 기술 설계에서 정한다.

### ERROR-04 최신 대화 재확인 — 확정 + 기술 설계

- AI가 판단하는 사이 새 메시지가 도착하면 최신 대화와 typing 상태를 재확인해 이미 불필요해진 개입을 게시하지 않는다.
- AI Host 메시지는 서버에서 한 번만 확정한다.
- 구체 freshness와 cancellation 방식은 기술 설계에서 정한다.

## 17. 제품 학습을 위한 기록

### OBS-01 분석 연결성 — 확정

다음 관계를 세션 단위와 AI 개입 단위로 분석할 수 있어야 한다.

> 상태·평가 → Policy Action → AI 개입 → 이후 대화 변화

사용자 Outcome은 MVP 앱 안의 설문 데이터로 수집하지 않는다.

### OBS-02 참가자 비노출 — 확정

내부 Discussion Metrics와 평가 로그는 참가자와 방장에게 노출하지 않는다.

### OBS-03 구체 이벤트·스키마 — 기술 설계

수집 이벤트, 식별자, 보관 기간, 민감정보 제거, 운영자 접근 권한은 기술 설계에서 정한다.

## 18. 기능 완료 기준

MVP 구현 완료는 다음 조건을 모두 만족할 때로 본다.

- 합의된 사용자 식별과 세션 참가 흐름이 동작한다.
- 선택적 사전 입력과 항목별 공개 범위가 동작한다.
- 실시간 텍스트 토론과 작성자 식별이 안정적으로 동작한다.
- 방장 권한과 일반 참가자 권한이 분리된다.
- AI가 `WAIT`를 포함한 단일 행동 목표를 선택할 수 있다.
- `AI_PRIVATE`가 Host, 로그, 결과물에서 누출되지 않는다.
- Living Wiki가 공개 근거 reference와 처리 기준점을 유지하고 오래된 갱신이 최신 버전을 덮어쓰지 않는다.
- Topic Checkpoint와 Final Wiki가 필요한 Raw Data를 다시 확인하며 Wiki 실패가 인간 대화를 막지 않는다.
- 반복 연장·마무리 결정과 종료 흐름이 동작한다.
- Synthesis, Closing, Final Wiki, 「오늘의 토론 기록」이 생성된다.
- 공식 종료 후 결과가 임의로 변경되지 않는다.
- 상태·Policy·AI 개입·이후 대화 변화의 분석 연결 로그가 저장된다.
- Book Context Pack이 7개 지식 section, 항목 성격, 출처·근거와 부족·충돌 상태를 보존한다.
- Evaluator와 Host가 room에 고정된 exact Pack version을 Provider로 사용한다.
- 운영자가 Book Context Pack의 항목·출처·불확실성을 검수하고 Publish할 수 있다.
- 핵심 제품 규칙, 권한, 프라이버시, 동시성 회귀 테스트가 통과한다.
