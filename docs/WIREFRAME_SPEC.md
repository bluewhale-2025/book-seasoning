> Last updated: 2026-09-02

## 0. 목적과 범위

이 문서는 핵심 토론 경험의 low-fidelity wireframe을 구현 가능한 화면 hierarchy와 상태 규칙으로 정리한다. 현재 범위는 다음 열한 화면이다.

1. 대기실
2. 실시간 토론
3. 연장 결정
4. Synthesis와 Closing
5. 오늘의 토론 기록
6. 프로필 설정
7. 토론 찾기와 참가
8. 토론 만들기
9. 내 토론
10. 방 설정
11. 로그인·회원가입·비밀번호 재설정

운영자 Builder는 별도 UX track에서 다룬다. 이번 문서는 제품 행동을 새로 결정하지 않으며 navigation과 정보 배치만 구체화한다.

참가자와 방장의 phase별 control 노출 기준은 `docs/ROLE_STATE_MATRIX.md`를 따른다.

## 1. 공통 화면 골격

### 1.1 App shell

Desktop navigation:

- 좌측: `책은양념` identity
- 가운데: `내 토론 / 토론 찾기` text navigation과 현재 위치 underline
- 우측: icon-only `토론 만들기`와 프로필 이름 첫 글자 avatar

`토론 만들기`의 plus icon은 accessible name과 tooltip을 제공한다. 생성 action은 destination navigation과 같은 underline 선택 상태로 표시하지 않는다.

Mobile navigation:

- 상단에는 hamburger, 가운데 service identity, 만들기 icon과 account menu avatar를 유지한다.
- hamburger menu는 `내 토론 / 토론 찾기 / 토론 만들기` 세 항목을 icon과 text row로 제공한다.
- 별도 하단 navigation을 만들지 않는다.
- 실시간 토론에서는 전역 navigation을 숨기고 토론 context header만 유지한다.
- 프로필 이미지는 업로드하지 않고 이름 첫 글자를 사용한다.

Account menu:

- 현재 이름, `프로필 설정`, `로그아웃`만 표시하고 이메일과 별도 신원 summary를 반복하지 않는다.
- `ADMIN`에게만 `운영` 구획과 `Book Context 관리`를 추가한다.
- menu open 시 첫 항목으로 focus를 이동하고 Escape로 닫은 뒤 avatar에 focus를 복귀한다.

### 1.2 Content hierarchy

- 일반 페이지: 최대 820~1040px shell
- 실시간 토론: 최대 720px conversation column
- page background는 흰색, 구조 구분은 border와 muted surface 중심
- 한 control group 안에서 primary action은 하나만 강조
- user-generated text는 bubble보다 문서형 흐름으로 표시

### 1.3 역할 차이

참가자와 방장은 별도 화면 mode를 사용하지 않는다. 같은 화면에서 역할별 control만 조건부로 노출한다.

- 참가자에게 사용할 수 없는 방장 control의 빈자리를 남기지 않는다.
- 방장 control은 시작, 연장 결정, AI 도움 요청처럼 필요한 시점에만 전면에 나타난다.
- 참가자 관리·방 설정·강제 종료는 session menu 안에 둔다.

## 2. WF-01 대기실

### 2.1 목표

- 참가자가 무엇을 기다리는지 이해한다.
- 사전 입력이 선택사항임을 이해한다.
- 각 항목의 공개 범위를 잘못 해석하지 않는다.
- 방장이 시작 가능 여부와 조건을 한 번에 확인한다.

### 2.2 정보 순서

1. 방 제목과 책 identity
2. 시작 예정 시각
3. 시작 상태와 인원
4. 내 사전 입력
5. 다른 참가자의 PUBLIC 사전 입력
6. 참가자 목록과 접속 상태

### 2.3 참가자 상단 상태

```text
시작 조건 충족
방장이 곧 토론을 시작할 예정이에요

등록 6 / 8명 · 현재 접속 4 / 시작 최소 4명
```

- 참가자에게 비활성 시작 버튼을 보여주지 않는다.
- 예정 시각 전이면 `오늘 오후 8시에 시작할 예정이에요`처럼 기다리는 이유를 설명한다.
- 접속 인원이 부족하면 부족한 인원을 표시하되 특정 오프라인 참가자를 압박하는 문구를 사용하지 않는다.

### 2.4 방장 시작 panel

```text
지금 시작할 수 있어요
시작 예정 시각과 최소 접속 인원을 충족했습니다

[토론 시작]
```

- 예정 시각 또는 최소 접속 인원 중 충족하지 않은 조건을 버튼 인접 영역에 표시한다.
- 등록 인원과 접속 인원을 각각 보여준다.
- start command 성공 전에는 토론이 시작된 것처럼 전환하지 않는다.

### 2.5 사전 입력

섹션 제목은 `토론 전에 생각을 남겨보세요 · 선택사항`으로 한다.

각 항목 row:

1. prompt
2. 현재 작성 내용 또는 빈 상태
3. 공개 범위 control
4. 저장 상태

공개 범위 control은 항목별로 둔다.

- `모두에게 공개`
- `AI에게만 공개`

`AI에게만 공개` 옆 또는 섹션 하단에 다음 설명을 지속적으로 제공한다.

> 원문과 작성자는 다른 참가자에게 보이지 않아요.

참가자별 사전 입력 완료 여부를 목록에 표시하지 않는다.

### 2.6 Responsive

대기실은 desktop에서도 주요 섹션을 두 열에 병치하지 않고 한 열로 쌓는다. 참가자 상태, 사전 입력과 PUBLIC 입력을 동시에 비교할 필요가 없고, 2-column은 정보 밀도와 시선 이동을 과도하게 높이기 때문이다.

Desktop과 Mobile 모두 다음 순서를 유지한다.

1. 시작 상태
2. 참가자 목록
3. 내 사전 입력
4. 다른 참가자의 PUBLIC 사전 입력

Desktop의 참가자 목록 내부에서만 3-column grid를 허용하고 Mobile에서는 2-column 또는 한 열로 reflow한다. 각 주요 섹션 사이는 card를 겹쳐 두기보다 38~48px의 명확한 vertical spacing으로 구분한다.

## 3. WF-02 실시간 토론

### 3.1 목표

- 책·현재 의제·시간을 잃지 않는다.
- 사람들의 대화가 가장 넓고 높은 비중을 차지한다.
- AI가 등장하지 않아도 화면이 비어 보이지 않는다.
- inline reply와 메시지 상태를 자연스럽게 이해한다.

### 3.2 상단 context

```text
[작은 표지] 소년이 온다 · 방 제목
토론 중 · 18:42 · 4명 접속

지금 나누는 질문
이 장면에서 침묵은 방관일까요, 살아남기 위한 선택일까요?
```

- scroll 전에는 책·방 정보를 보여주고, scroll 후에는 compact state로 축소할 수 있다.
- 참가자에게 보이는 label은 `현재 이야기` 대신 `지금 나누는 질문`을 사용한다.
- Opening과 Core Discussion에서는 현재 질문을 sticky하게 유지한다.
- 연장 결정 중에도 현재 질문을 유지해 대화를 계속할 수 있게 한다.
- Synthesis에서는 이 영역을 `지금까지 나온 생각`으로 전환하고, Closing에서는 제거한다.
- Mobile sticky question은 최대 두 줄로 줄이고 펼쳐볼 수 있게 한다.
- 단계와 참가 가능 여부를 같은 badge로 합치지 않는다.

### 3.3 Message timeline

- 참가자 메시지는 avatar, 이름, 시각, 본문으로 구성한다.
- 같은 참가자의 연속 메시지는 avatar와 이름을 반복하지 않는다.
- inline reply는 작성자와 짧은 인용을 본문 위에 표시한다.
- message body는 약 62ch를 넘지 않는다.
- 과거를 읽는 중 새 메시지가 오면 자동 scroll하지 않고 `새 메시지 N개`를 제공한다.
- 메시지 전체를 말풍선으로 감싸지 않고 문서형 흐름을 유지한다.
- 답장 action은 hover·focus에서는 메시지 우측에, touch에서는 메시지를 누른 뒤 같은 위치에 노출한다.
- `새 메시지 N개`를 누르면 첫 미확인 메시지로 이동하고 divider를 읽음 처리한다.
- 최신 위치에 있을 때만 새 메시지를 자연스럽게 이어 붙이며, 매 메시지마다 화면 전체를 재정렬하지 않는다.

메시지 delivery state는 본문 아래의 작은 status line으로 표시한다.

```text
전송 중…

전송하지 못했어요  [다시 보내기]
```

- pending 메시지는 작성자 본인에게만 보이는 약한 상태로 두되 본문은 그대로 읽을 수 있게 한다.
- failed 메시지는 timeline에서 사라지거나 composer를 덮어쓰지 않는다.
- retry는 같은 메시지를 다시 보내는 행동이며 복제된 새 메시지처럼 보이지 않게 한다.
- 확정된 메시지에는 수정·삭제 action을 제공하지 않는다.

### 3.4 AI Host

AI 발언은 참가자와 다른 구조를 사용한다.

```text
책은양념 · AI Host
두 분은 같은 침묵을 각각 책임과 생존의 문제로 보고 있네요…
```

- 참가자 avatar를 사용하지 않는다.
- 차분한 surface, marker와 divider를 사용한다.
- AI typing animation이나 자동 평가 중 상태는 표시하지 않는다.
- 방장 요청으로 생성된 경우에만 `방장 요청으로 개입` label을 추가한다.
- 좋은 인간 대화에서는 AI block이 전혀 없는 상태를 기본으로 본다.
- AI 발언에는 reply action을 제공할 수 있지만 일반 참가자 메시지처럼 avatar나 말풍선을 붙이지 않는다.
- 자동 개입 실패는 참가자 timeline에 오류로 남기지 않는다.

### 3.5 Composer

- 2,000자·여러 줄 입력
- inline reply target
- 보내기
- 전송 중·실패·다시 보내기
- typing 상태

기본 placeholder는 `생각을 나눠보세요`를 사용한다. 답장할 메시지를 선택하면 textarea 위에 작성자와 한두 줄 인용을 보여주고 icon-only `답장 취소`를 함께 제공한다. `Enter`는 전송, `Shift + Enter`는 줄바꿈이며 조합 입력 중에는 전송하지 않는다.

보내기·답장·답장 취소·다시 보내기는 익숙한 icon을 사용하고 accessible name과 tooltip을 제공한다. `Shift + Enter`, 최대 글자 수, 저장 완료 같은 도움말은 항상 노출하지 않고 첫 사용·focus·제한 근접·오류 상황에서만 보여준다.

재연결 중에는 draft를 유지하고 composer를 잠근다. 공식 종료 또는 Closing에서는 일반 composer를 제거한다. 입력 중인 참가자 이름은 composer 위 timeline 마지막에 한 줄로 표시하며 매초 반복해서 읽어주지 않는다.

### 3.6 연결·동기화 상태

- 연결이 끊기면 기존 timeline과 작성 중 draft를 화면에 유지한다.
- current question 아래에 `대화를 다시 맞추고 있어요` 상태를 표시하고 composer와 방장 운영 control만 잠근다.
- 놓친 메시지·현재 질문·단계·남은 시간·참가자 상태의 동기화가 끝난 뒤 입력을 다시 연다.
- 동기화 실패 시 `다시 연결` action을 제공하되 사용자가 작성한 draft를 지우지 않는다.
- 늦게 들어온 참가자에게는 blocking modal 대신 `토론이 이미 진행 중이에요`라는 한 줄 context를 보여주고 현재 질문과 남은 시간을 바로 확인하게 한다.

### 3.7 방장 contextual control

방장도 참가자와 같은 토론 화면을 사용한다. 별도 운영 mode나 상시 관리 panel을 만들지 않고 상단 context에 다음 icon-only control만 추가한다.

```text
[참가자] [AI 도움] [더보기]
```

- 각 icon은 accessible name과 tooltip을 제공한다.
- `AI 도움`은 Opening, Core Discussion, 연장 중에만 노출한다.
- `AI 도움`을 열면 `대화가 멈춤 / 논의가 반복됨 / 주제에서 벗어남 / 갈등 정리 필요` 네 사유를 선택하고 text button `요청하기`로 확정한다. 자유 입력은 제공하지 않는다.
- 요청 처리 중에는 해당 icon 안의 progress indicator와 방장에게만 보이는 tooltip `흐름 확인 중`으로 충분하며 큰 상태 banner를 만들지 않는다.
- 실패하면 icon에 error marker를 표시하고 열었을 때 `다시 시도`를 제공한다. 다른 참가자에게는 실패 상태를 노출하지 않는다.
- 참가자 icon은 participant sheet를 연다. 각 참가자 row의 `더보기` menu에서 `방장 권한 이전`, `참가자 내보내기`를 text label로 제공한다.
- session `더보기` menu에는 참가 비밀번호 변경, 나가기, 토론 종료처럼 자주 쓰지 않는 운영 action을 둔다.
- `방장 권한 이전`, `참가자 내보내기`, `토론 종료`는 icon만으로 실행하지 않는다. 대상과 영향을 명시한 확인 dialog와 구체적인 실행 동사를 사용한다.
- 운영 command는 server 성공 이후에만 화면 state를 바꾸며 실패 시 기존 권한과 참가자 상태를 유지한다.

## 4. WF-03 연장 결정

### 4.1 목표

- 종료가 가까웠다는 사실을 모든 참가자가 이해한다.
- AI의 의견과 방장의 결정권을 혼동하지 않는다.
- 결정 중에도 인간 대화가 멈추지 않는다.

### 4.2 위치

blocking modal을 사용하지 않고 current topic 아래 session state region에 표시한다. timeline과 composer는 계속 사용할 수 있다.

### 4.3 모든 참가자에게 표시

```text
토론 종료까지 7분
대화를 더 이어갈지 결정할 시간이에요

AI 의견 · 연장 추천
새로운 관점이 계속 연결되고 있어 15분 더 이야기해볼 가치가 있어 보여요.
```

AI 의견 생성 실패 시 recommendation 영역을 생략하거나 짧은 실패 안내로 대체하되 방장 결정 control은 유지한다.

### 4.4 참가자 상태

```text
방장의 결정을 기다리고 있어요
5분이 되면 자동으로 마무리를 시작합니다
```

### 4.5 방장 control

```text
[15분 연장] [마무리하기]
AI 의견과 관계없이 방장이 결정합니다
```

- 두 선택의 의미를 명확히 하되 primary/secondary hierarchy가 선택을 강요하지 않게 조정한다.
- `마무리하기`는 destructive action이 아니다.
- 5분 경계까지 응답하지 않으면 자동으로 Synthesis로 이동한다.

## 5. WF-04 Synthesis와 Closing

### 5.1 Synthesis

AI 정리는 다음 구조로 보여준다.

1. 오늘 갈린 관점 2~4개
2. 각 관점의 핵심 근거
3. 연결 또는 충돌
4. 짧은 reflection 요청

불일치를 합의된 결론처럼 보이게 하는 시각 구조를 사용하지 않는다. 관점은 병렬로 배치하되 작은 화면에서는 순서대로 쌓는다.

### 5.2 Closing 전환

Closing이 시작되면:

- phase는 `마무리 중`
- 일반 composer 제거
- 최대 5분 별도 countdown
- 마지막 한 줄 input 제공
- 다른 참가자의 제출 내용은 숨김

### 5.3 마지막 한 줄

```text
선택사항 · 다른 사람의 답은 종료 후 공개됩니다
오늘 대화 후 가장 남는 생각을 한 문장으로 남겨주세요

[최대 300자 입력]
[건너뛰기] [마지막 한 줄 제출]
```

- 제출 후에도 Closing 종료 전까지 수정·삭제 가능
- 제출 여부를 참가자 이름과 함께 공개하지 않음
- 현재 접속자 전원이 제출 또는 건너뛰기를 완료하면 조기 종료 가능
- 방장에게 별도의 Closing 조기 마감 control을 제공하지 않음

## 6. WF-05 오늘의 토론 기록

### 6.1 목표

- 시간순 회의록보다 공동 사고의 구조를 먼저 이해한다.
- 익명화된 공식 기록과 이름이 붙는 마지막 한 줄을 구분한다.
- 기록 생성 지연에도 원본 대화에 접근할 수 있다.

### 6.2 첫 화면 hierarchy

1. 책·방·종료 시각·실제 참여자 수
2. local navigation: `오늘의 토론 기록 / 전체 대화 / 사전 입력`
3. 오늘의 핵심 쟁점
4. 관점 지도
5. 오늘 생긴 변화와 확장
6. 남은 질문
7. 참가자의 마지막 한 줄

### 6.3 이름 정책

- 쟁점, 관점, 변화, 남은 질문: 이름 없음
- 마지막 한 줄: 제출 당시 이름 표시
- 전체 대화: 당시 작성자 이름과 시각 표시
- AI_PRIVATE: 작성자 본인 외에는 표시하지 않음

### 6.4 생성 상태

- `생성 중 / 재시도 중`은 record content 영역에만 표시
- 전체 대화와 방·책 정보는 즉시 열람 가능
- 자동 재시도가 모두 실패한 경우 방장에게만 `다시 생성하기`
- 공식 기록 성공 후 재생성 control 제거

실패 역할 차이, 대화 부족, 원본 대화와 사전 입력의 privacy projection은 `docs/DISCUSSION_RESULTS_UX.md`를 따른다.

- 예정된 방의 방장은 권한 이전 또는 방 취소 필요
- `ADMIN`은 역할 해제 필요
- 최종 확인 시 현재 password 요구

첫 화면에는 `계정 탈퇴 알아보기`처럼 설명 단계로 진입시키고, 즉시 password와 최종 action을 함께 노출하지 않는다.

탈퇴 blocker별 다음 행동, 삭제·익명 유지 범위와 최종 확인은 `docs/PROFILE_ACCOUNT_UX.md`를 따른다.

## 8. WF-07 토론 찾기와 참가

### 8.1 목표

- 한 화면에서 방 제목·책·저자를 검색한다.
- 진행 상태와 참가 가능 여부를 혼동하지 않는다.
- 검색 결과를 보는 것과 실제 참가 등록을 구분한다.

### 8.2 검색 결과

첫 화면 상단에는 넓은 editorial heading과 `방 제목, 책, 저자 검색` 단일 search를 둔다. search 실행은 field 끝의 익숙한 icon button으로 축약한다.

검색 전 browse 영역은 서버가 가진 room state만 사용해 다음 두 section으로 나눈다.

- `곧 시작해요`: 시작 예정 시각이 가까운 시작 전 room
- `지금 참여 가능`: 공식 종료 전이며 정원이 남은 진행 중 room

장르, 인기, 추천과 개인화 ranking은 추가하지 않는다. Desktop은 한 section에서 최대 3개 card를 동시에 보여주고 mobile은 한 card에 집중한 뒤 `다음` icon으로 순서를 넘긴다. room 전용 image를 요구하지 않고 책 표지를 dominant visual로 사용한다.

각 browse card와 search result의 정보 순서는 다음과 같다.

1. 책 표지
2. 방 제목
3. 책 제목·저자
4. 방장 이름·시작 예정 시각
5. 현재/최대 인원
6. 진행 상태
7. `참여 가능 / 정원 마감`

- `토론 중`과 `참여 가능`은 독립 label로 표시한다.
- 참가자 명단과 참가 패스워드는 result row에 표시하지 않는다.
- 공식 종료·취소된 방은 검색 결과에서 제외한다.
- card 전체로 상세에 진입한다.
- 정원 마감 card도 상세 정보는 볼 수 있지만 참가 input은 제공하지 않는다.

### 8.3 참가 패스워드

- 방 상세의 `참가하기`를 누른 뒤 password field를 보여준다.
- field에는 `보기 / 숨기기` icon을 제공하고 계정 password와 다른 `참가 패스워드`임을 label로 구분한다.
- `참가하기`는 membership을 만드는 의미가 있으므로 text label을 유지한다.
- 오입력 시 값을 비우고 `패스워드가 올바르지 않습니다`만 인접해 표시한다.
- 정원 경합으로 실패하면 `방금 정원이 마감되었습니다`를 표시하고 input을 잠근다.
- 기존 등록자·방장·실제 참여자는 password 대신 `대기실로 돌아가기 / 토론으로 돌아가기`를 본다.

### 8.4 시작 후 참가 확인

password 통과 후 바로 composer로 보내지 않고 다음 context를 확인한다.

```text
토론 중 · 12:18 남음
지금 나누는 질문
이 장면에서 침묵은 방관일까요, 살아남기 위한 선택일까요?
현재 4 / 최대 8명

[토론에 참여하기]
```

- `토론에 참여하기`를 실행한 시점에 실제 참여자로 확정한다.
- 기존 PUBLIC 사전 입력과 사전 입력 form은 보여주지 않는다.
- `마무리 중`이면 현재 마무리 단계라는 사실을 진행 상태와 함께 표시한다.

## 9. WF-08 토론 만들기

### 9.1 단계 구조

```text
1 책 선택 → 2 토론 정보 → 3 확인
```

- 현재 단계는 짧은 label과 `n / 3`으로 표시하고 완료 단계 설명을 반복하지 않는다.
- 단계 이동 시 선택한 책과 입력값을 유지한다.
- 이전 단계는 icon-only back으로 이동하고 `다음`, `토론 만들기`는 text label을 유지한다.

### 9.2 책 선택

- Published Book Context Pack이 연결된 책만 노출한다.
- 검색창 하나로 제목·저자를 검색한다.
- `최근 추가된 순 / 제목 가나다순 / 저자 가나다순` 정렬을 제공한다.
- 각 항목은 표지, 제목, 저자, 출판사, 출간연도를 표시하고 선택 후 짧은 소개를 펼친다.
- 결과가 없으면 `아직 토론이 준비된 책이 없습니다`를 표시하며 책 등록·요청 action은 제공하지 않는다.

### 9.3 토론 정보

필수 field:

- 방 제목
- 시작 예정 시각
- 참가 패스워드 4~20자
- 최소 참가 인원
- 최대 참가 인원

인원은 숫자와 icon-only 증감 control로 입력한다. 기본 화면에 수식을 설명으로 반복하지 않고 잘못된 조합이 생겼을 때만 `최소 인원은 최대 인원보다 클 수 없습니다`처럼 inline validation을 제공한다.

### 9.4 확인과 생성

- 선택한 책, 방 제목, 시작 예정 시각, 최소·최대 인원을 한 번에 확인한다.
- 참가 패스워드는 기본적으로 가리고 `보기` icon으로만 확인한다.
- 최종 action은 `토론 만들기` text button을 사용한다.
- server 성공 전에는 생성된 방으로 전환하지 않는다.
- 생성 완료 후 대기실로 이동하고 참가 패스워드는 서비스 밖에서 직접 전달한다는 짧은 안내를 한 번만 제공한다.

## 10. WF-09 내 토론

### 10.1 분류와 정렬

상단에는 `진행 중 / 예정 / 종료` 세 tab과 각 개수만 둔다.

- `진행 중`: 현재 다시 입장할 수 있는 방, 최근 진행 상태 우선
- `예정`: 시작 예정 시각이 가까운 순
- `종료`: 최근 종료 순, 취소된 방 포함

사용자가 만든 방과 참가한 방은 별도 목록으로 나누지 않고 각 row에 `방장 / 참가자` 역할을 표시한다. 통계, 추천 토론, 참여율 같은 MVP 밖 dashboard 정보는 추가하지 않는다.

### 10.2 토론 row

정보 순서:

1. 책 표지
2. 방 제목
3. 책 제목·저자
4. 역할
5. 진행 상태
6. 시작 예정 시각 또는 종료 시각
7. 현재/최대 인원

- row 전체가 진입 control이며 별도 `입장하기 / 보기` text button을 반복하지 않는다.
- 진행 중 row는 실시간 토론, 예정 row는 대기실, 종료 row는 읽기 전용 기록으로 이동한다.
- 취소된 row는 열 수 없고 `취소됨`과 원래 예정 시각만 확인한다.
- 정상 상태 설명과 관리 menu를 row마다 반복하지 않는다.

### 10.3 빈 상태

- 전체가 비어 있으면 `토론 찾기`와 `토론 만들기`를 함께 제공한다.
- `진행 중`만 비어 있으면 별도 행동을 강요하지 않고 예정 토론을 확인할 수 있게 한다.
- `예정`이 비어 있으면 `토론 찾기`, `종료`가 비어 있으면 행동 없이 짧은 빈 상태만 표시한다.

## 11. WF-10 방 설정

### 11.1 진입과 기본 구조

방장에게만 대기실·실시간 토론의 `더보기` menu 안에서 `방 설정`을 제공한다. 설정 화면은 다음 순서를 유지한다.

1. 현재 책과 토론 identity
2. 변경 가능한 설정
3. 저장
4. 토론 취소 또는 토론 종료

참가자에게 비활성 설정 화면이나 권한 안내를 노출하지 않는다.

### 11.2 시작 전 설정

편집 가능:

- 방 제목
- 시작 예정 시각
- 참가 패스워드
- 최소 참가 인원
- 최대 참가 인원

책은 방장 외 등록 참가자가 없을 때만 `책 변경` action을 제공한다. 다른 참가자가 있으면 현재 책과 `참가자가 있어 책을 변경할 수 없어요`만 표시하고 비활성 input을 만들지 않는다.

인원은 만들기 화면과 같은 icon-only 증감 control을 사용한다. 저장 전에는 변경 내용을 local state로 유지하고 `변경사항 저장` text button 하나로 확정한다.

### 11.3 진행 중 설정

방 제목, 책, 시작 시각, 최소 인원은 읽기 전용 요약으로 보여준다. 편집 control은 다음 두 항목만 제공한다.

- 참가 패스워드: 변경 후 신규 참가자에게만 적용
- 최대 참가 인원: 현재 등록 인원 이상, 최대 15명

불가능한 감소·증가 control은 비활성화한다. 잠긴 항목마다 같은 설명을 반복하지 않는다.

### 11.4 위험 action

시작 전에는 `토론 취소`, 시작 후에는 `토론 종료`만 제공한다. 일반 설정과 충분한 간격을 두고 분리한다.

취소 확인:

```text
이 토론을 취소할까요?
검색에서 사라지고 등록된 참가자의 자리가 모두 해제됩니다.

[돌아가기] [토론 취소]
```

종료 확인:

```text
지금 토론을 종료할까요?
대화 입력이 닫히고 다시 시작할 수 없습니다. 지금까지 확정된 내용으로 기록을 만듭니다.

[돌아가기] [토론 종료]
```

- dialog는 대상 방 제목을 포함한다.
- 실행 동사는 icon-only로 축약하지 않는다.
- server 성공 전에는 취소·종료된 상태로 전환하지 않는다.

## 12. WF-11 로그인·회원가입·비밀번호 재설정

### 12.1 공통 shell

인증 전에는 global navigation을 표시하지 않는다. `책은양념` identity와 최대 420px 한 열 form만 중앙에 두고 화면마다 목적을 하나로 제한한다.

- 비밀번호 field의 보기·숨기기는 icon-only control과 accessible name을 사용한다.
- form submit은 text button을 유지하고 처리 중에는 button 내부 progress만 표시한다.
- provider 원문 error와 계정 존재 여부를 노출하지 않는다.
- 성공 전에는 보호된 app shell이나 가입 완료 상태를 먼저 보여주지 않는다.

### 12.2 로그인

정보 순서:

1. `로그인`
2. 이메일
3. 비밀번호
4. `비밀번호를 잊으셨나요?`
5. `로그인`
6. `회원가입`

로그인 실패는 이메일과 비밀번호 중 어느 값이 잘못되었는지 구분하지 않고 `이메일 또는 비밀번호를 확인해주세요`를 action 바로 위에 표시한다. CAPTCHA는 기본 상태에 표시하지 않는다.

### 12.3 회원가입

필수 field:

- 프로필 이름
- 이메일
- 비밀번호

프로필 이름 field label은 `프로필 이름`을 사용하고 `토론에서 보이는 이름`을 짧은 보조 label로 붙인다. 별도 사용자명, 프로필 이미지, 이메일 확인 동의 단계를 추가하지 않는다.

- 공백 이름은 field error로 처리한다.
- 중복 이메일은 `이미 사용 중인 이메일입니다`를 이메일 field에 연결한다.
- 가입 성공 시 이메일 확인 대기 화면 없이 로그인 상태가 되고 `내 토론`으로 이동한다.
- Turnstile managed challenge가 사용자 입력을 요구할 때만 submit 인접 영역에 나타난다.

### 12.4 비밀번호 재설정 요청

요청 화면은 이메일 field와 `재설정 메일 받기`만 제공한다. 제출 후 이메일 존재 여부와 관계없이 다음 동일 상태를 표시한다.

```text
재설정 안내를 확인해주세요
입력한 이메일이 가입되어 있다면 비밀번호 재설정 메일이 도착합니다.

[로그인으로 돌아가기]
```

재전송 countdown, 받은편지함 열기, 다른 메일 서비스 link는 MVP에 추가하지 않는다.

### 12.5 새 비밀번호와 link 오류

유효한 callback:

- 새 비밀번호
- 새 비밀번호 확인
- `비밀번호 변경`

두 값이 다르면 확인 field에만 오류를 표시한다. 완료 후 `비밀번호가 변경되었습니다`와 `로그인`을 제공한다.

만료되거나 이미 사용된 link:

```text
재설정 링크가 만료되었어요
[재설정 메일 다시 받기]
```

token, 만료 시각과 provider 오류 코드는 표시하지 않는다.

## 13. 공통 상태와 접근성

### 13.1 독립 상태 축

다음 상태를 하나의 badge나 enum으로 합치지 않는다.

- session phase
- 참가 가능 여부
- connection state
- message delivery state
- 사용자의 역할

### 13.2 Keyboard와 focus

- stage의 primary action까지 logical tab order 유지
- dialog open/close 시 focus 이동·복귀
- icon-only action에 accessible name 제공
- reply action은 hover뿐 아니라 focus와 touch에서 사용 가능
- hidden role control은 tab order에서도 제거

### 13.3 Screen reader announcement

- timer 매초 announcement 금지
- 7분·5분·1분, Closing 시작·종료만 안내
- 최신 위치를 보고 있을 때만 새 message polite announcement
- 과거를 읽는 중에는 `새 메시지 N개`만 안내
- typing 상태 반복 announcement 금지
