# 프로필·계정 설정 UX 기준

> Status: Proposed UX baseline  
> Product source of truth: `PRODUCT_SPEC.md` §3.1, §3.2, §17.1  
> Related decisions: `docs/DECISIONS.md` PRODUCT-003, PRODUCT-029  
> Last updated: 2026-09-02

## 0. 목적과 범위

프로필 설정은 토론에서 보이는 이름과 계정 보안을 관리하는 조용한 한 열 화면이다. 자주 실행하는 이름 저장과 되돌릴 수 있는 계정 action은 짧게 유지하고, 계정 탈퇴만 영향 확인 → 조건 확인 → 현재 비밀번호 → 최종 확인 순으로 분리한다.

MVP 범위:

- 프로필 이름 확인·변경
- 계정 이메일 읽기 전용 표시
- 비밀번호 재설정 진입
- 로그아웃
- 계정 탈퇴 가능 조건과 영향 확인
- 현재 비밀번호를 요구하는 최종 탈퇴

MVP에서 제외:

- 프로필 이미지 업로드
- 세션별 nickname과 고유 handle
- 이메일 변경, 소셜 계정 연결
- 데이터 내보내기
- 탈퇴 유예·복구
- ADMIN 역할 관리 UI

## 1. 진입과 공통 구조

- app header의 첫 글자 avatar를 눌러 account menu를 열고 `프로필 설정`으로 진입한다.
- desktop과 mobile 모두 최대 540px 한 열을 사용한다.
- 본문에 별도 신원 요약을 만들지 않는다. app header avatar가 현재 사용자를 이미 나타내므로 이름과 이메일은 설정 항목에서 각각 한 번만 표시한다.
- 첫 화면은 `이름 변경 → 계정 3개 행 → 계정 탈퇴 진입`의 단일 흐름으로 축약한다.
- field와 row의 label만으로 역할이 분명하면 `프로필`, `계정`, `로그인과 보안` 같은 중간 제목을 반복하지 않는다.
- 설정 page에 토론 통계, 활동 점수, 참여 횟수와 추천을 추가하지 않는다.
- account menu와 하위 화면은 열고 닫을 때 focus를 이동·복귀한다.

## 2. 프로필 이름

- 본문에는 avatar와 현재 이름 요약을 반복하지 않고, `프로필 이름` input 하나가 현재 값을 직접 보여준다.
- input과 `저장` text action을 같은 행에 둔다.
- 이름은 다른 사용자와 중복될 수 있으므로 중복 검사 상태를 만들지 않는다.
- 공백만 있는 이름은 inline validation으로 거절한다.
- 저장 성공 전에는 header avatar를 먼저 바꾸지 않는다.
- 저장 후 새 메시지와 새 토론에 적용한다.
- `새 메시지·새 토론부터 적용 · 과거 기록의 이름은 유지`를 form 아래 한 번만 표시한다.
- 프로필 이미지 추가·편집 control을 제공하지 않는다.

## 3. 계정

- 별도 계정 소개 영역 없이 `이메일 / 비밀번호 재설정 / 로그아웃` 세 행만 둔다.
- 로그인 이메일은 첫 행에 읽기 전용 text로 한 번만 표시하고 edit icon을 제공하지 않는다.
- `비밀번호 재설정`은 별도 인증 흐름으로 이동하는 text row다. 정상 상태 설명 문장은 붙이지 않는다.
- `로그아웃`은 명확한 text action으로 유지한다.
- 계정 비밀번호와 방 참가 패스워드를 같은 화면에서 섞지 않는다.

## 4. 계정 탈퇴 정보 단계

기본 설정 화면에는 `계정 탈퇴 알아보기`만 둔다. 현재 비밀번호와 최종 destructive action을 첫 화면에 바로 노출하지 않는다.

정보 단계는 다음 영향을 두 그룹으로 구분한다.

삭제:

- 이메일, 비밀번호 정보, 현재 프로필 이름과 계정 설정
- 모든 `AI_PRIVATE` 사전 입력과 private-derived 상태

공동 기록에 익명으로 유지:

- 원본 채팅, `PUBLIC` 사전 입력, 마지막 한 줄의 내용
- 이미 확정된 익명 공식 토론 기록
- 작성자 이름은 `탈퇴한 사용자`로 변경

추가 규칙:

- 일반 참가자의 시작 전 참가 등록은 탈퇴 시 자동 취소한다.
- 탈퇴는 복구할 수 없다.
- 같은 이메일로 다시 가입할 수 있지만 이전 계정과 참여 기록은 복구되지 않는다.

## 5. 탈퇴 가능 조건

정보 단계에 들어오면 server가 탈퇴 가능 조건을 확인한다.

### 5.1 진행 중 실제 참여

- 공식 종료 전에는 탈퇴할 수 없다.
- 진행 중인 토론의 identity와 `토론으로 돌아가기` 경로를 제공한다.
- 종료 예상 시각을 임의로 약속하지 않는다.

### 5.2 예정된 방의 방장

- 먼저 방장 권한을 이전하거나 토론을 취소해야 한다.
- 대상 예정 토론 row 전체를 방 설정 진입 control로 사용한다.
- 프로필 화면 안에 방장 이전·취소 form을 복제하지 않는다.

### 5.3 ADMIN

- 역할을 수동 해제한 뒤 탈퇴할 수 있다.
- MVP에는 role management UI를 만들지 않고 운영 담당자에게 역할 해제를 요청하도록 안내한다.
- 일반 사용자에게 ADMIN 조건이나 화면을 노출하지 않는다.

### 5.4 탈퇴 가능

- blocker가 없으면 `계속`을 제공한다.
- 일반 참가자의 예정 membership 자동 취소는 blocker가 아니라 영향 항목이다.

## 6. 현재 비밀번호와 최종 확인

- 최종 화면에는 현재 비밀번호 field와 보기·숨기기 icon-only control을 둔다.
- 비밀번호가 비어 있으면 `계정 탈퇴`를 비활성화한다.
- 비밀번호 오류는 field 인접 `현재 비밀번호를 확인해 주세요`로 표시하고 값을 유지해 다시 입력할 수 있게 한다.
- provider 원문 오류와 계정 상태를 노출하지 않는다.
- 비밀번호 검증 후 대상과 되돌릴 수 없음을 다시 확인하는 dialog를 연다.
- 최종 실행 label은 `계정 탈퇴`를 유지하고 icon-only로 축약하지 않는다.
- server 성공 전에는 로그아웃되거나 삭제 완료 화면으로 전환하지 않는다.
- 실패하면 계정과 로그인 상태를 유지하고 재시도할 수 있게 한다.

## 7. 탈퇴 완료

- 보호된 app shell을 제거하고 인증 전 shell에서 `계정이 삭제되었습니다`를 표시한다.
- `로그인`과 `회원가입` 경로를 제공할 수 있다.
- 같은 이메일로 새 가입은 가능하지만 이전 계정이 복구되는 것처럼 표현하지 않는다.
- 삭제된 계정의 프로필 이름·이메일을 완료 화면에 다시 표시하지 않는다.

## 8. 반응형과 접근성

- 320px에서도 form과 영향 목록을 한 열로 유지하고 horizontal page scroll을 만들지 않는다.
- icon-only back, password visibility와 dialog close에는 accessible name과 tooltip을 제공한다.
- validation은 `role="alert"`, 저장·삭제 처리 상태는 `aria-live="polite"`로 전달한다.
- 위험 action은 색만으로 의미를 전달하지 않고 `계정 탈퇴` text label을 사용한다.
- dialog open/close focus 이동·복귀와 native tab order를 유지한다.
- password manager와 브라우저 자동완성을 방해하는 가짜 input을 만들지 않는다.

## 9. 검증 시나리오

1. 이름을 변경하고 저장 전·후 header avatar의 차이를 확인한다.
2. 공백 이름이 저장되지 않고 field error가 연결되는지 확인한다.
3. 이메일 변경이나 프로필 이미지 업로드 control이 없는지 확인한다.
4. 탈퇴 정보에서 삭제 정보와 익명 유지 공동 기록을 구분할 수 있는지 확인한다.
5. 진행 중 실제 참여, 예정 방장과 ADMIN blocker별 다음 행동을 이해할 수 있는지 확인한다.
6. 같은 이메일로 다시 가입할 수 있다는 제품 규칙과 이전 계정 복구 불가를 혼동하지 않는지 확인한다.
7. 현재 비밀번호 전에는 최종 탈퇴를 실행할 수 없는지 확인한다.
8. 최종 dialog focus 이동·복귀와 server 성공 전 상태 보존을 확인한다.
9. 320px와 keyboard-only에서 이름 저장과 탈퇴 확인을 완료한다.

## 10. 인터랙티브 시안 검증 결과

2026-09-02 기준 `profile-account.html` 축약 시안에서 다음을 확인했다.

- 별도 신원 요약과 계정 소개 heading을 제거해 현재 이름과 이메일이 첫 화면에 각각 한 번만 나타난다.
- 이름을 바꾸면 저장 action이 활성화되고 저장 후에만 header의 첫 글자 avatar가 변경된다.
- 공백 이름은 inline error로 표시되고 저장되지 않는다.
- 진행 중 실제 참여, 예정 토론 방장, ADMIN 역할 blocker가 서로 다른 다음 행동을 표시한다.
- 현재 비밀번호가 비어 있으면 탈퇴 action이 비활성화되고 오류 입력은 field 인접 alert로 표시된다.
- 최종 dialog open 시 닫기 control로 focus가 이동하고 닫힌 뒤 실행 control로 복귀한다.
- 탈퇴 확정 후 보호된 app shell이 제거되고 완료 화면으로 전환된다.
- 1200px, 736px과 320px 검증 환경의 실제 content width 273–288px에서 8개 상태와 dialog에 horizontal overflow가 없다.
- 모든 icon-only button에 accessible name이 있고 duplicate id가 없으며 프로필 이미지·이메일 변경·소셜 연결·데이터 내보내기 control이 없다.
