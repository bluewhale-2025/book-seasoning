# 참가자·방장 권한별 상태 매트릭스

> Status: Proposed interaction baseline  
> Product source of truth: `PRODUCT_SPEC.md` §3, §4, §10, §11, §12  
> UX baseline: `docs/UX_PLAN.md`, `docs/WIREFRAME_SPEC.md`  
> Last updated: 2026-09-02

## 0. 목적

같은 토론 화면에서 참가자와 방장에게 필요한 control만 조건부로 노출하기 위한 기준이다. 방장을 별도 mode나 dashboard로 분리하지 않고, `role × session phase × membership × connection`을 독립적으로 판정한다.

이 문서는 새로운 권한을 만들지 않는다. 제품 권한이 바뀌면 먼저 `PRODUCT_SPEC.md`와 Product Decision을 갱신한다.

## 1. 독립 상태 축

| 축 | 값 | UI 의미 |
| --- | --- | --- |
| Role | 일반 회원 / 일반 참가자 / 방장 / ADMIN | 보이는 운영 control을 결정한다. 방장과 ADMIN은 서로 다른 권한이다. |
| Membership | 미등록 / 참가 등록 / 실제 참여 / 내보내짐 | 입장, 정원 점유와 종료 후 열람 가능 여부를 결정한다. |
| Phase | 시작 예정 / 시작 대기 / 토론 중 / 연장 결정 / 연장 중 / Synthesis / Closing / 종료 / 취소됨 | 입력 종류와 단계 action을 결정한다. |
| Connection | 접속 중 / 재연결 중 / 오프라인 | 입력 가능 여부만 바꾼다. membership이나 실제 참여를 취소하지 않는다. |
| Capacity | 참여 가능 / 정원 마감 | 신규 membership 생성 가능 여부다. 기존 등록자 재입장과 분리한다. |
| Delivery | 작성 중 / 전송 중 / 실패 / 확정 | 메시지 한 건의 상태다. session phase와 합치지 않는다. |

### 1.1 Membership 판정

- `참가 등록`: 시작 전 패스워드 통과 시 생성되고 최대 인원을 점유한다.
- `실제 참여`: 세션 시작 후 실시간 토론방에 처음 들어간 시점에 확정한다.
- 시작 전에 등록했지만 종료까지 실시간 토론방에 들어오지 않은 일반 참가자는 종료 후 열람권이 없다.
- 방장은 실제 불참 여부와 관계없이 방 관리와 종료 후 접근권을 유지한다.
- 내보낸 참가자는 기존 메시지가 보존되어도 현재 방과 종료된 기록을 더 이상 열람할 수 없다.

## 2. Phase별 화면과 권한

| Phase | 모든 허용 사용자에게 보임 | 일반 참가자 | 방장에게만 추가 | 입력 상태 |
| --- | --- | --- | --- | --- |
| 검색·상세 | 방·책, 방장, 예정 시각, 인원, 진행 상태, 참가 가능 여부 | 미등록이면 참가 패스워드, 기존 등록자면 재입장 action | 자신의 방은 패스워드 없이 대기실 이동 | 채팅 없음 |
| 시작 예정 | 예정 시각, 등록·접속 인원, 참가자 상태, 선택적 사전 입력 | 사전 입력 작성·공개 범위 변경, 시작 전 참가 취소 | 방 설정, 참가자 관리, 권한 이전, 방 취소; 시작 action은 예정 시각 전 비활성 사유 표시 | 사전 입력만 활성 |
| 시작 대기 | 방장이 시작할 예정임, 현재 접속 인원과 최소 인원 | 대기와 사전 입력 | 최소 인원 충족 시 `토론 시작`; 미달이면 부족 인원과 함께 비활성 | 사전 입력만 활성 |
| Opening·Core | 현재 의제, 남은 시간, 참가자, 메시지·reply | 메시지 작성, 나가기 후 공식 종료 전 재입장 | AI 도움 요청, 참가자 관리, 권한 이전, 방 설정 일부, 토론 종료 | 채팅 활성 |
| 연장 결정 | 종료 임박, AI의 연장·마무리 의견 또는 의견 실패 | 결정 결과를 기다리며 채팅 계속 | 2분 동안 `15분 연장 / 마무리하기`; AI 의견과 무관하게 선택 | 채팅 활성 |
| 연장 중 | 새 종료 시각, 연장 중 상태, 현재 의제 | 메시지 작성, 자유 퇴장·재입장 | Opening·Core와 같은 운영 control, 다음 종료 7분 전에 재결정 | 채팅 활성 |
| Synthesis | AI 관점 정리와 reflection 요청, 남은 토론 시간 | reflection 응답 | AI 도움 요청과 연장 control 없음; 토론 종료만 유지 | 일반 대화보다 reflection 중심 |
| Closing | 마지막 한 줄 선택사항, Closing 남은 시간, 기존 대화 읽기 | 한 줄 작성·수정·삭제 또는 건너뛰기 | 일반 Closing 조기 마감 없음; 긴급 `토론 종료`만 가능 | 일반 채팅 닫힘, 한 줄만 활성 |
| 종료 | 방·책, 실제 참여자, 전체 대화, PUBLIC 사전 입력, 공식 기록과 마지막 한 줄 | 실제 참여자만 읽기 전용 열람 | 최초 공식 기록 생성이 재시도 소진으로 실패한 경우에만 재생성 | 모든 입력 닫힘 |
| 취소됨 | 취소 사실과 참가 등록 해제 | 취소 이력만 확인 | 추가 운영 action 없음 | 모든 입력 닫힘 |

## 3. Control 노출 매트릭스

| Control | 일반 참가자 | 방장 | 조건과 presentation |
| --- | --- | --- | --- |
| 참가 패스워드 | 미등록 상태에서만 | 표시하지 않음 | 기존 등록자·실제 참여자는 비밀번호 없이 재입장한다. |
| 시작 전 참가 취소 | 표시 | 표시하지 않음 | 일반 참가자에게만 제공하고 확인 후 membership과 정원 점유를 제거한다. |
| 사전 입력 | 본인 항목 작성·수정 | 동일 | 시작 전까지만. `PUBLIC / AI에게만 공개`를 선택한다. |
| 다른 사람의 PUBLIC 입력 | 읽기 | 읽기 | 시작 전 등록자에게만. AI_PRIVATE 존재 여부도 추론 가능하게 표시하지 않는다. |
| 방 설정 | 표시하지 않음 | 표시 | 시작 전 전체 허용 범위, 시작 후 패스워드와 최대 인원만 편집한다. |
| 토론 시작 | 표시하지 않음 | 표시 | 예정 시각 이후 + 현재 접속 인원 충족. 불충족이면 disabled와 이유를 함께 표시한다. |
| 메시지·reply | 표시 | 동일 | Opening, Core, 연장 중 활성. 재연결 중에는 초안을 보존하고 잠시 비활성화한다. |
| 토론 화면 나가기 | 표시 | 동일 | 공식 종료 전 재입장 가능함을 확인한다. membership은 제거하지 않는다. |
| AI 도움 요청 | 표시하지 않음 | 표시 | Opening, Core, 연장 중만. 자유 입력 없이 4개 사유 중 하나를 선택한다. |
| 참가자 내보내기 | 표시하지 않음 | 표시 | 시작 전 등록자 또는 진행 중 참가자를 대상으로 이름·영향 확인 후 실행한다. |
| 방장 권한 이전 | 표시하지 않음 | 표시 | 시작 전 등록자, 시작 후 실제 참여자에게만 이전한다. 완료 후 기존 방장은 일반 참가자가 된다. |
| 15분 연장 / 마무리 | 결과만 봄 | 표시 | 남은 시간 7분부터 5분까지. 일반 참가자 투표는 없다. |
| 토론 종료 | 표시하지 않음 | 표시 | 시작 후에만 제공하는 destructive text action. Synthesis·Closing을 건너뛸 수 있음을 확인한다. |
| 마지막 한 줄 | 표시 | 동일 | 실제 참여자만 Closing 동안 하나를 제출·수정·삭제하거나 건너뛴다. |
| 공식 기록 재생성 | 표시하지 않음 | 조건부 표시 | 최초 생성의 자동 재시도가 모두 실패했을 때만. 성공한 공식 기록에는 표시하지 않는다. |

## 4. 보이지 않아야 하는 control

권한이 없는 control은 disabled 자리로 남기지 않고 DOM과 tab order에서 제거한다.

- 일반 참가자의 시작, 연장 결정, AI 도움 요청, 방 설정, 참가자 관리와 토론 종료
- Synthesis·Closing의 AI 도움 요청
- Closing의 일반 채팅 composer와 조기 마감
- 종료 후 메시지, 사전 입력, 마지막 한 줄과 공식 기록 수정·삭제
- 미등록자·no-show·내보내진 참가자의 종료 기록 열람
- 일반 사용자 account menu의 `Book Context 관리`

예외적으로 같은 역할이 조건만 충족하면 곧 사용할 control은 disabled 상태와 이유를 보여줄 수 있다.

- 예정 시각 전 방장의 `토론 시작`
- 최소 접속 인원 미달의 `토론 시작`
- 현재 등록 인원보다 작은 최대 인원 값
- 다른 참가자가 등록한 뒤의 책 변경

## 5. 위험 action과 서버 확정

다음 action은 icon-only로 축약하지 않고 대상, 영향과 실행 동사를 명시한 확인 단계를 거친다.

- 참가자 내보내기
- 방장 권한 이전
- 토론방 취소
- 토론 종료

시작, 연장, 마무리, 권한 이전, 내보내기와 종료는 server 성공 이후에만 확정 상태로 전환한다. 충돌 시 현재 authoritative state를 다시 동기화하고 사용자가 방금 선택한 결과를 낙관적으로 확정하지 않는다.

## 6. Privacy·관찰 불변식

- 방장에게도 AI_PRIVATE 원문, 작성자와 존재 여부를 노출하지 않는다.
- Discussion Metrics, Participant State, AI 판단 로그를 참가자와 방장 화면에 표시하지 않는다.
- 접속 상태는 `접속 중 / 오프라인`만 제공하며 마지막 접속 시각, 발언량, 침묵 여부와 활동 점수를 표시하지 않는다.
- 내보낸 참가자의 기존 메시지는 원본 기록에 남지만 해당 참가자의 접근권은 제거한다.
- 종료된 공동 기록은 읽기 전용이며 공개 링크·SNS 공유·파일 내보내기를 제공하지 않는다.

## 7. 구현·검증 체크리스트

1. Role, phase, membership, connection을 하나의 enum이나 badge로 합치지 않는다.
2. 참가자와 방장의 기본 화면 hierarchy가 같고 방장 control만 필요한 위치에 추가되는지 확인한다.
3. 모든 phase에서 일반 참가자 DOM에 방장 전용 control이 존재하지 않는지 검사한다.
4. 연장 결정의 AI 의견 실패가 방장 선택을 막지 않는지 확인한다.
5. 재연결 중 draft 보존, 입력 잠금과 authoritative sync 후 복구를 확인한다.
6. Closing에서 일반 채팅과 다른 참가자의 미공개 마지막 한 줄이 노출되지 않는지 확인한다.
7. no-show, 내보내진 참가자, 실제 참여자와 방장의 종료 후 접근권을 각각 검증한다.
8. destructive confirmation과 server 실패 시 기존 상태 보존을 확인한다.
